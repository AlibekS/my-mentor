# L2 Quest — программа и правила для авторов контента

Трек для владельца с уровнем **L1**, цель — **L2 → L3 / Production Support в иностранной SaaS-компании**.
L2 Quest лежит в `content/l2/modules/<id>/` в том же формате, что и L3 (`content/modules/…`, см. README и
CLAUDE.md): `module.json`, `lessons/NN-slug.md` (теория) + `lessons/NN-slug.ts` (`export default LessonDef`),
по желанию `data.ts`. Модуль: **4–5 уроков + босс** (`kind: 'boss'`, `incident`), урок: `tasks` 3–5 (лимит теста 2–6),
`quiz` 3–5 (choice ≤ 1/3), `hints` ≤ 3, `glossary`. Входного теста (placement) у L2 нет.

## Программа

`order` в module.json — номер модуля (1–8); `requires: []` (порядок задаёт программа); `importance` 3–5;
`reviewedAt: "2026-11-05"`, `demand: "stable"|"rising"`, `status: "ready"`, `estimatedMinutes`.
Lesson id уникален внутри модуля; ключ урока = `<module id>/<lesson id>`.

## Уровень и стиль

- Читатель — L1: знает ПК и базовую поддержку, Linux и SQL почти не видел. **Объясняй с нуля**, каждую команду
  и термин — простыми словами и на примере; маленькие шаги; урок 15–25 минут; без ловушек и «подвохов».
- Сценарии — **SaaS-продукт** (интернет-магазин/CRM/платёжный сервис), клиенты из разных стран, тикеты в
  Zendesk/Jira. Не корпоративный ИТ (Windows/AD/принтеры).
- Каждый урок заканчивается мостом к работе: «как это выглядит в тикете», «что написать в эскалации».
- Русский, грамотно; термины — парой «первопричина (root cause)».
- Задания проверяют **результат**, а не конкретную команду (см. правила в CLAUDE.md: синонимы RU/EN в `accept`,
  основы слов в `keywords`, `outputMatches`/состояние/`custom` вместо точного формата). Числа — вычислять из данных.
  Время — `keywords`. Решение (`solution`) обязано проходить свою проверку; задание не должно быть решено до решения.

## Английский — постепенно (владелец: реально A2+/B1-)

- **Модули 1–2:** термины RU/EN в `glossary`; в конце теории каждого урока блок `## 🇬🇧 English corner` —
  3–5 рабочих фраз «по-английски — перевод» (например, *Could you send me a screenshot?* — Пришлите скриншот?).
- **Модули 3–5:** + в каждом уроке одно задание, где входные данные на английском (сообщение клиента, лог,
  текст ошибки); отвечать можно по-русски (`accept`/`keywords` — RU и EN).
- **Модули 6–7:** + 1–2 вопроса мини-теста на простом английском; тикеты от иностранных клиентов на английском.
- **Модуль 8:** письменные задания на английском (`write: { lang: 'en', rubric, template }`): ответ клиенту,
  статья в базу знаний, эскалация в L3. Рубрики — щадящие (ключевые элементы: приветствие, суть, шаги, срок,
  вежливое завершение), английский уровня B1, в теории — шаблоны фраз с переводом. Подсказки — на русском.
- Английский текст — короткими простыми предложениями; новые слова поясняй в скобках по-русски.

## Инструменты

- Терминал: `scenario` (файлы, сервисы, сеть) — эмулятор Linux, ~105 команд, см. `src/shell/commands`.
- SQL: `sql: { dataset }` — строка SQL (CREATE TABLE + INSERT, SQLite), можно собрать в `data.ts` модуля.
- DevTools: `devtools: DevtoolsDataset` (`src/devtools/types.ts`): `page`, `screen` (что видит клиент),
  `requests[]` (method, url, status, type, size, timeMs, startMs, request/responseHeaders, payload, response,
  timing, error для `status: 0`), `console[]`, `cookies[]`, `storage`. Задания по DevTools — **через `answer`**
  (исследуй вкладки → введи ответ). Урок с `devtools` показывает тренажёр вместо терминала.
- Письменные задания: `write: { rubric: [{ label, any: [regex…], none?, minMatches? }], minWords, template, lang }`.

## Проверка

`npx vitest run content/__tests__/content.test.ts` — должен быть зелёным (эталонные решения проходят проверки,
нет самозасчёта, уникальные ключи, feedsL3 ссылаются на модули L3). Затем `npx tsc --noEmit -p .`.
