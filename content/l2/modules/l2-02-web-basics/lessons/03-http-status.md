# HTTP-запрос, ответ и коды состояния

Каждый ответ сервера начинается с **кода состояния (status code)** — трёхзначного числа, которое коротко говорит, чем кончилось дело. Для L2 это первая и самая важная улика: по одному числу видно, **чья это проблема** — клиента, сети или нашего сервера.

## Как выглядит HTTP изнутри

Запрос клиента — это несколько строк текста:

```
GET /v1/orders/1043 HTTP/1.1          ← метод, путь, версия протокола
Host: api.shopflow.kz                 ← заголовки (headers)
User-Agent: curl/8.5.0
Accept: */*
```

Ответ сервера:

```
HTTP/1.1 200 OK                       ← статусная строка: код и пояснение
Content-Type: application/json        ← заголовки ответа
Date: Wed, 04 Nov 2026 09:30:00 GMT

{"id":1043,"status":"failed"}         ← тело ответа (body)
```

Три части ответа: **статусная строка** (код), **заголовки** (служебная информация, урок 4), **тело** (сама страница или данные).

## Пять классов кодов

Первая цифра кода — его класс. Запомни таблицу, и половина диагностики у тебя в голове:

| Класс | Смысл | Чья проблема | Частые коды |
|---|---|---|---|
| **1xx** | информационные | — | редко встречаются в поддержке |
| **2xx** | **успех** | всё хорошо | 200 OK, 201 Created, 204 No Content |
| **3xx** | **перенаправление** | не ошибка: «ищи по другому адресу» | 301 Moved Permanently, 302 Found, 304 Not Modified |
| **4xx** | **ошибка клиента** (запроса) | неверный запрос: адрес, данные, доступ | 400, 401, 403, 404, 429 |
| **5xx** | **ошибка сервера** | у нас что-то сломалось | 500, 502, 503, 504 |

## Коды, которые L2 видит каждый день

**4xx — «запрос неправильный»:**
- **400 Bad Request** — сервер не понял запрос: неверный формат данных.
- **401 Unauthorized** — «кто ты?»: нет входа или токена, либо он истёк.
- **403 Forbidden** — «знаю, кто ты, но тебе нельзя»: нет прав (например, роль «менеджер» не видит финансы).
- **404 Not Found** — такого адреса или объекта нет: опечатка в URL, удалённый заказ.
- **429 Too Many Requests** — слишком много запросов, сработал лимит (rate limit).

**5xx — «сломалось у нас»:**
- **500 Internal Server Error** — приложение упало с ошибкой при обработке запроса. Почти всегда — к L3 с request id.
- **502 Bad Gateway** — прокси перед приложением не получил от него нормальный ответ (приложение упало или не запущено).
- **503 Service Unavailable** — сервис временно не принимает запросы: перегрузка или плановые работы.
- **504 Gateway Timeout** — приложение не успело ответить вовремя.

Главное правило: **4xx — сначала смотрим, что отправил клиент; 5xx — смотрим на себя**. Но если 4xx внезапно посыпались у многих клиентов сразу после релиза — это уже наша проблема.

## curl: как увидеть код

Три способа, от простого к удобному:

```
curl -I https://shopflow.kz/pricing-old
```
`-I` — запросить **только заголовки** (без тела). Первая строка — код: `HTTP/1.1 301 Moved Permanently`.

```
curl -i https://api.shopflow.kz/v1/orders/99999
```
`-i` — заголовки **и** тело вместе. Удобно, когда в теле есть описание ошибки.

```
curl -s -o /dev/null -w "%{http_code}\n" https://api.shopflow.kz/v1/orders/99999
```
Только код, одним числом. Разберём по кусочкам:
- `-s` (silent) — не показывать полосу загрузки;
- `-o /dev/null` — тело ответа выбросить (`/dev/null` — «чёрная дыра», всё, что туда записано, исчезает);
- `-w "%{http_code}\n"` (write-out) — после запроса напечатать код ответа и перевод строки.

Такую команду удобно запускать для нескольких адресов подряд и сразу видеть, какой из них «красный».

## Тело ошибки — читай его!

Хорошие API в теле ошибки объясняют, что случилось:

```json
{"error":"order_not_found","message":"Order 99999 does not exist"}
```

А в ответе 500 часто есть **request id** — его L2 прикладывает к эскалации:

```json
{"error":"internal_error","request_id":"req_5d1e07"}
```

## Как это выглядит в тикете

> **Клиент:** Ваш API не работает! Интеграция с нашим складом сломалась.
>
> **L2:** `curl -i` на адрес из их логов: `404`, тело `order_not_found`. API работает — склад запрашивает заказ 99999, которого нет. Отвечаем клиенту: «API отвечает, но заказа 99999 у вас нет — проверьте, откуда склад берёт этот номер».

> **Другой клиент:** Не выгружается отчёт.
>
> **L2:** `curl -i` → `500`, в теле `request_id: req_5d1e07`. Это наша ошибка: эскалация в L3 с request id, временем и шагами.

Одна команда — и понятно, кто должен действовать.

## 🇬🇧 English corner

Термины: *status code* — код состояния, *client error* — ошибка клиента (4xx), *server error* — ошибка сервера (5xx), *redirect* — перенаправление, *not found* — не найдено, *bad gateway* — плохой шлюз.

- *The server returns a 500 error.* — Сервер возвращает ошибку 500.
- *The endpoint responds with 404 Not Found.* — Адрес (эндпоинт) отвечает 404 «не найдено».
- *This is a server-side issue.* — Это проблема на стороне сервера.
- *Please check the request on your side.* — Пожалуйста, проверьте запрос на вашей стороне.
