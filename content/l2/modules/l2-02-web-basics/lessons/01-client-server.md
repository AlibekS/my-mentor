# Клиент, сервер и URL

Каждый день клиенты ShopFlow пишут: «сайт не открывается», «админка тормозит», «API возвращает ошибку». Чтобы разбираться в таких тикетах, L2 должен понимать, **что происходит между нажатием Enter в браузере и появлением страницы**. Это проще, чем кажется.

## Клиент и сервер

- **Клиент (client)** — тот, кто **просит**: браузер покупателя, мобильное приложение, программа клиента, которая вызывает наш API, или ты с командой `curl` в терминале.
- **Сервер (server)** — тот, кто **отвечает**: компьютер ShopFlow в дата-центре, на котором работает наше приложение.

Общаются они по правилам протокола **HTTP** (HyperText Transfer Protocol). Схема всегда одна:

```
Клиент  ──── запрос (request) ────▶  Сервер
        ◀──── ответ (response) ────
```

Запрос: «дай мне страницу /admin/orders». Ответ: «вот она» (код 200) или «такой нет» (404), или «у меня ошибка» (500). Коды разберём в уроке 3.

## Что происходит, когда открываешь сайт

Покупатель вводит `https://nomad-outdoor.shopflow.kz/catalog` и нажимает Enter:

1. **DNS.** Браузер не знает, где находится `nomad-outdoor.shopflow.kz`. Он спрашивает DNS — «телефонную книгу интернета»: «какой IP-адрес у этого имени?». Ответ: `203.0.113.20`. (Урок 2.)
2. **Соединение.** Браузер подключается к серверу по этому IP на порт 443 и договаривается о шифровании (HTTPS).
3. **Запрос.** Браузер отправляет HTTP-запрос: «GET /catalog».
4. **Ответ.** Сервер возвращает код, заголовки и тело — HTML страницы.
5. **Отрисовка.** Браузер показывает страницу и догружает картинки, стили, скрипты — каждое отдельным запросом.

Сломаться может на любом шаге, и для L2 важно понять **на каком**: «имя не находится» (DNS), «сервер не отвечает» (сеть), «сервер ответил ошибкой» (приложение). От этого зависит, кому передавать тикет и что писать в эскалации.

## URL по частям

**URL** (Uniform Resource Locator) — полный адрес ресурса. Разберём на примере из тикета:

```
https://nomad-outdoor.shopflow.kz:8443/admin/orders?status=failed&page=2
└─┬─┘   └──────────┬────────────┘ └┬─┘└─────┬────┘ └────────┬────────┘
протокол         домен (host)     порт    путь (path)   параметры (query)
```

| Часть | В примере | Что значит |
|---|---|---|
| **Протокол (scheme)** | `https` | как общаться. `https` — с шифрованием, `http` — без |
| **Домен, хост (host)** | `nomad-outdoor.shopflow.kz` | имя сервера; DNS превратит его в IP |
| **Порт (port)** | `8443` | «номер двери» на сервере. Если не указан: для https — **443**, для http — **80** |
| **Путь (path)** | `/admin/orders` | какая страница или ресурс на сервере |
| **Параметры (query)** | `status=failed&page=2` | уточнения после `?`, пары `имя=значение`, разделены `&` |

Ещё бывает **якорь (fragment)** после `#` — например `#reviews`; он не уходит на сервер, его использует только браузер.

### Зачем L2 разбирать URL

- Клиент прислал ссылку с ошибкой — по **домену** видно, какой это магазин, по **пути** — какая страница, по **параметрам** — какие фильтры он выбрал. Это готовые шаги воспроизведения.
- Видишь нестандартный **порт** (`:8443`) — возможно, корпоративный фаервол клиента его не пропускает.
- Видишь `http://` вместо `https://` — возможно, клиент открыл старую закладку.

## API — сайт для программ

**API** (Application Programming Interface) — это «вход для программ». Браузер получает HTML, красивую страницу для человека. А API отвечает **JSON** — данными в формате, удобном для программ:

```json
{"pong":true,"region":"eu-central","version":"4.12.1"}
```

Клиенты ShopFlow подключают к нашему API свои системы: 1С, складской учёт, CRM. Когда интеграция ломается, тикет приходит к L2 — и смотреть мы будем через `curl`.

## curl — браузер в терминале

`curl` отправляет HTTP-запрос и печатает ответ. Самый простой вариант:

```
curl https://api.shopflow.kz/v1/ping
```

Ответ сервера — тело (body) — появится прямо в терминале. Никаких картинок и кнопок: только то, что сервер на самом деле прислал. Поэтому L2 и L3 так любят curl: он показывает **факты** без влияния браузера, кэша и расширений.

## Как это выглядит в тикете

Клиент: «У нас не грузится список неудачных заказов, вот ссылка: https://nomad-outdoor.shopflow.kz:8443/admin/orders?status=failed&page=2».

L2 сразу видит: магазин `nomad-outdoor`, страница заказов, фильтр `status=failed`, вторая страница списка, и — странный порт 8443 (наша админка работает на стандартном 443). Первый вопрос клиенту: «Откуда эта ссылка? Попробуйте открыть без `:8443`». Половина таких тикетов решается за минуту.

## 🇬🇧 English corner

Термины: *client* — клиент, *server* — сервер, *request / response* — запрос / ответ, *URL* — адрес, *host / domain* — домен, *path* — путь, *query parameters* — параметры запроса.

- *Could you send me the full URL?* — Пришлите, пожалуйста, полный адрес (URL).
- *The page does not load.* — Страница не загружается.
- *Please try to open the link without the port.* — Попробуйте открыть ссылку без порта.
- *The API returns an error.* — API возвращает ошибку.
