# DNS: как имя превращается в адрес

Компьютеры в интернете находят друг друга по **IP-адресам** — числам вроде `203.0.113.12`. Людям такие числа запоминать неудобно, поэтому придумали имена: `api.shopflow.kz`. Превращает имя в адрес **DNS (Domain Name System)** — «телефонная книга интернета».

Если DNS не работает или настроен неправильно, сайт «не открывается», хотя сам сервер в полном порядке. Для SaaS-поддержки это одна из самых частых причин тикетов «у нас всё упало» — особенно когда клиент подключает **свой домен** к магазину.

## Как это работает (просто)

1. Браузер спрашивает DNS-сервер: «какой IP у `api.shopflow.kz`?»
2. DNS-сервер отвечает: «`203.0.113.12`».
3. Браузер запоминает ответ на время **TTL** (time to live — «время жизни», в секундах) и идёт по этому адресу.

## Типы записей, которые нужны L2

| Запись | Что делает | Пример |
|---|---|---|
| **A** | имя → IPv4-адрес | `api.shopflow.kz → 203.0.113.12` |
| **CNAME** | имя → **другое имя** (псевдоним) | `www.nomad-outdoor.kz → shops.shopflow.kz` |
| **MX** | куда доставлять почту домена | `nomad-outdoor.kz → mail.provider.com` |
| **TXT** | текстовые настройки (подтверждение домена, SPF для писем) | `"v=spf1 include:shopflow.kz ~all"` |

**CNAME** особенно важен в SaaS. Клиент хочет, чтобы его магазин открывался по адресу `www.nomad-outdoor.kz`, а не `nomad-outdoor.shopflow.kz`. Для этого он у своего регистратора домена создаёт запись: `www.nomad-outdoor.kz CNAME shops.shopflow.kz`. Теперь DNS отвечает: «это псевдоним для shops.shopflow.kz, а у того IP такой-то». Если клиент ошибся в CNAME (опечатка, старый адрес из старой инструкции) — его магазин не откроется, и чинить это должен **клиент** в своей DNS-панели, а L2 объясняет, что именно поправить.

## Команда dig

`dig` (domain information groper) — главный инструмент для проверки DNS:

```
dig api.shopflow.kz            # подробный ответ
dig +short api.shopflow.kz     # только результат (IP или цепочка имён)
```

Подробный вывод выглядит страшно, но смотреть нужно на две вещи:

```
;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 41022     ← статус запроса
...
;; ANSWER SECTION:                                            ← сам ответ
www.nomad-outdoor.kz.   300   IN   CNAME   shops.shopflow.kz.
shops.shopflow.kz.      300   IN   A       203.0.113.20
```

- **status: NOERROR** — имя существует, ответ есть.
- **status: NXDOMAIN** (non-existent domain) — **такого имени нет**. Опечатка, домен не зарегистрирован или запись забыли создать.
- В **ANSWER SECTION** — сами записи: имя, TTL (300 секунд), тип (A, CNAME) и значение.

Точка на конце имени (`shops.shopflow.kz.`) — нормальная часть записи DNS, на неё не обращай внимания.

## Команда nslookup

`nslookup` — то же самое, только проще и есть даже в Windows (пригодится, чтобы попросить клиента выполнить проверку у себя):

```
nslookup api.shopflow.kz
```

```
Non-authoritative answer:
Name:    api.shopflow.kz
Address: 203.0.113.12
```

Если имени нет — увидишь `** server can't find …: NXDOMAIN`.

## Типичные DNS-проблемы в тикетах

| Что пишет клиент | Что показывает dig | Что значит |
|---|---|---|
| «Сайт не открывается» | `NXDOMAIN` | опечатка в адресе или записи нет |
| «Свой домен не работает после подключения» | CNAME указывает не туда | клиент ошибся в настройке у регистратора |
| «У меня открывается, у коллеги — нет» | у всех правильный ответ | старый ответ в кэше у коллеги: подождать TTL или очистить кэш |
| «Открывается старый сайт» | старый IP | запись поменяли недавно, кэш ещё не обновился |

## Как это выглядит в тикете

> **Клиент:** Подключили домен shop.astana-flowers.kz по вашей инструкции, но магазин не открывается.
>
> **L2 (internal note):** `dig shop.astana-flowers.kz` — CNAME указывает на `old-shops.shopflow.kz`, а по актуальной статье KB должен быть `shops.shopflow.kz`. Клиент взял адрес из старой инструкции.
>
> **L2 (ответ клиенту):** Здравствуйте! Мы проверили ваш домен: запись CNAME указывает на старый адрес old-shops.shopflow.kz. Пожалуйста, измените её на shops.shopflow.kz в панели вашего регистратора. Изменения вступают в силу в течение часа.

Обрати внимание: L2 не просто сказал «у вас DNS неправильный», а показал **что именно** и **на что поменять**.

## 🇬🇧 English corner

Термины: *DNS record* — DNS-запись, *domain* — домен, *resolve* — разрешить (имя в адрес), *NXDOMAIN* — домен не существует, *CNAME* — псевдоним, *TTL* — время жизни записи, *registrar* — регистратор домена.

- *The domain does not resolve.* — Домен не разрешается (DNS не даёт адрес).
- *Your CNAME record points to the old address.* — Ваша запись CNAME указывает на старый адрес.
- *Please update the DNS record at your registrar.* — Пожалуйста, обновите DNS-запись у вашего регистратора.
- *DNS changes can take up to an hour.* — Изменения DNS могут занять до часа.
