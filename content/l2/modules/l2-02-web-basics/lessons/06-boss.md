# 👹 Босс модуля: «Магазин не открывается, оплата падает»

**Среда, 11:20 UTC.** Приходит тикет от Nomad Outdoor (тариф Business):

> **ZD-3500.** Здравствуйте! У части покупателей не открывается наш магазин **nomad-outdoor.kz** — «сайт недоступен». А те, кто всё-таки заходит через **www.nomad-outdoor.kz**, не могут оплатить: «Ошибка оплаты». Мы теряем продажи, помогите!

Две жалобы в одном тикете. Возможно, у них **разные причины** — и разные люди должны их чинить. Твоя задача — разделить проблемы и для каждой собрать факты.

## Что у тебя есть

```
~/tickets/ZD-3500.txt                   тикет клиента
~/kb/custom-domain.md                   инструкция по подключению своего домена
https://status.shopflow.kz/api/v2/components.json   статус компонентов платформы (JSON)
```

API оформления оплаты (так его вызывает витрина магазина):

```
POST https://api.shopflow.kz/v1/checkout/sessions
```

## Цепочка действий L2

1. **DNS.** Куда указывает домен `nomad-outdoor.kz`? Сравни с инструкцией.
2. **Работает ли www.** Какой код отвечает `https://www.nomad-outdoor.kz/`? Если 200 — витрина в порядке, и проблема первой жалобы именно в DNS основного домена.
3. **Оплата.** Повтори запрос витрины к API оформления оплаты — методом **POST**. Какой код вернулся?
4. **Request id.** Найди `X-Request-Id` этого ответа — его приложим к тикету.
5. **Статус платформы.** Посмотри страницу статуса через `jq`: какие компоненты сейчас **не** в состоянии `operational`? Может быть, это уже известный инцидент.

## Напоминалка

```
dig имя / dig +short имя / nslookup имя          # DNS
curl -s -o /dev/null -w "%{http_code}\n" URL     # только код
curl -i -X POST URL                              # POST: заголовки + тело
curl -s URL | jq '.components[] | select(.status != "operational") | .name'
```

## Что будет дальше (после босса)

Если всё найдёшь, ответ клиенту получится примерно такой: «Проблема 1 — на вашей стороне: домен nomad-outdoor.kz указывает на устаревший адрес, исправьте запись CNAME на shops.shopflow.kz. Проблема 2 — на нашей: у платёжного провайдера сбой, это известный инцидент, инженеры уже работают, следующее обновление — в 12:00 UTC». Одна проблема — инструкция клиенту, другая — связь с инцидентом. Никаких «у нас всё работает» и никаких «мы всё починим», когда чинить должен клиент.

## 🇬🇧 English corner

Термины: *status page* — страница статуса, *component* — компонент (часть платформы), *major outage* — крупный сбой, *degraded performance* — работает с перебоями, *operational* — работает нормально.

- *There are two separate issues.* — Здесь две отдельные проблемы.
- *Your domain points to an outdated address.* — Ваш домен указывает на устаревший адрес.
- *Our payment provider is experiencing an outage.* — У нашего платёжного провайдера сбой.
- *You can follow the updates on our status page.* — Следить за обновлениями можно на нашей странице статуса.
