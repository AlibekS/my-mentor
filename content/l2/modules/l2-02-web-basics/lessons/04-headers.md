# Заголовки HTTP: служебная информация ответа

Код ответа говорит «что случилось», а **заголовки (headers)** — подробности: куда перенаправить, через сколько повторить, сколько хранить в кэше, какой номер у запроса. Заголовки — это строки вида `Имя: значение` между статусной строкой и телом ответа.

```
HTTP/1.1 429 Too Many Requests        ← статусная строка
Content-Type: application/json        ← заголовки
Retry-After: 60
X-RateLimit-Limit: 100
X-RateLimit-Remaining: 0
X-Request-Id: req_c40b19
                                      ← пустая строка — конец заголовков
{"error":"rate_limit_exceeded"}       ← тело
```

## Заголовки, которые нужны L2

| Заголовок | Что значит | Когда смотреть |
|---|---|---|
| **Content-Type** | что в теле: `text/html` (страница), `application/json` (данные), `image/png` | «вместо данных пришла HTML-страница» — часто признак ошибки прокси |
| **Location** | новый адрес при перенаправлении (3xx) | «ссылка ведёт не туда», бесконечные редиректы |
| **Retry-After** | через сколько **секунд** можно повторить запрос | с кодами 429 и 503 |
| **X-RateLimit-Limit / Remaining** | лимит запросов и сколько осталось | интеграция клиента получает 429 |
| **Cache-Control** | можно ли хранить ответ в кэше и сколько (`max-age` в секундах) | «после обновления вижу старую версию» |
| **X-Request-Id** | уникальный номер запроса | **всегда** — прикладываем к эскалации |
| **Set-Cookie** | сервер сохраняет cookie в браузере (например, сессию входа) | проблемы со входом (подробно — в модуле про браузер) |

Заголовки, начинающиеся с `X-`, — нестандартные, их придумывает сама компания. У ShopFlow есть `X-Request-Id`, у других SaaS он может называться `X-Correlation-Id` или `Request-Id`.

## Как посмотреть заголовки

```
curl -I https://api.shopflow.kz/v1/products
```

`-I` (или `--head`) — запросить **только заголовки**. Самый быстрый способ.

```
curl -i https://api.shopflow.kz/v1/products
```

`-i` — заголовки **и** тело: видно и `Retry-After`, и текст ошибки.

```
curl -v https://api.shopflow.kz/v1/products
```

`-v` (verbose, «подробно») — весь разговор целиком. Строки со знаком `>` — то, что **отправил** curl, строки со знаком `<` — что **ответил** сервер:

```
> GET /v1/products HTTP/1.1          ← наш запрос
> Host: api.shopflow.kz
> User-Agent: curl/8.5.0
>
< HTTP/1.1 429 Too Many Requests     ← ответ сервера
< Retry-After: 60
```

`-v` полезен, когда нужно доказать, **что именно** мы отправили и получили.

## Rate limit: «вы слишком часто спрашиваете»

API ShopFlow разрешает интеграции 100 запросов в минуту. Если склад клиента отправляет больше — сервер отвечает **429** и заголовками подсказывает:
- `X-RateLimit-Limit: 100` — лимит;
- `X-RateLimit-Remaining: 0` — осталось 0;
- `Retry-After: 60` — повтори через 60 секунд.

Это не наша авария: L2 объясняет клиенту, что его интеграция превышает лимит, и советует делать паузы между запросами или повторять после `Retry-After`.

## Кэш: «я вижу старую версию»

`Cache-Control: public, max-age=86400` значит: браузер и CDN (сеть серверов-кэшей) могут хранить ответ **86 400 секунд** — это 24 часа (86 400 / 3600). Если файл поменяли, у части пользователей старая версия может «жить» до суток. Типичный совет: обновить страницу с очисткой кэша (Ctrl+F5) или открыть в режиме инкогнито.

Перевод секунд — частая операция:
- 60 с = 1 минута
- 3600 с = 1 час
- 86 400 с = 1 сутки

## Location и перенаправления

Ответ `301`/`302` без заголовка `Location` бесполезен — именно Location говорит, куда идти. Посмотреть: `curl -I старый-адрес`. Пройти по перенаправлению автоматически — `curl -L` (follow Location).

## Как это выглядит в тикете

> **Клиент:** Наш склад перестал получать товары через API, ошибка 429.
>
> **L2 (internal note):** `curl -i https://api.shopflow.kz/v1/products` с токеном клиента: `429`, `X-RateLimit-Limit: 100`, `Retry-After: 60`, `X-Request-Id: req_c40b19`. Лимит превышен.
>
> **L2 (клиенту):** Ваша интеграция отправляет больше 100 запросов в минуту — это лимит тарифа. Повторяйте запрос через время из заголовка Retry-After (60 секунд) или распределите запросы равномернее. Если нужен больший лимит — подскажем по тарифам.

Request id в заметке — на случай, если клиент будет спорить: L3 найдёт этот запрос в логах.

## 🇬🇧 English corner

Термины: *header* — заголовок, *rate limit* — ограничение частоты запросов, *cache* — кэш, *redirect* — перенаправление, *verbose* — подробный.

- *You have exceeded the rate limit.* — Вы превысили лимит запросов.
- *Please retry after 60 seconds.* — Пожалуйста, повторите через 60 секунд.
- *Please clear your browser cache.* — Пожалуйста, очистите кэш браузера.
- *Could you share the X-Request-Id header?* — Пришлите, пожалуйста, заголовок X-Request-Id.
