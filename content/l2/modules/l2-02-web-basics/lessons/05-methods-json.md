# Методы HTTP, JSON и jq

До сих пор мы только **читали**: открывали страницы, смотрели коды и заголовки. Но клиенты ShopFlow через API ещё и **создают** заказы, **меняют** статусы, **удаляют** товары. Что именно хочет сделать запрос, говорит **метод (method)** — первое слово в запросе.

## Основные методы

| Метод | Что делает | Пример в ShopFlow | Успешный ответ |
|---|---|---|---|
| **GET** | получить, прочитать | `GET /v1/orders/1043` — данные заказа | 200 OK |
| **POST** | создать, запустить действие | `POST /v1/orders` — создать заказ; `POST /v1/orders/1043/retry` — повторить оплату | 201 Created / 202 Accepted |
| **PUT / PATCH** | изменить | `PATCH /v1/orders/1043` — поменять адрес доставки | 200 OK |
| **DELETE** | удалить | `DELETE /v1/products/77` | 204 No Content |

Если отправить не тот метод (например, GET туда, где ждут POST), сервер ответит **405 Method Not Allowed**, а в заголовке `Allow` перечислит, какие методы можно.

**Важно для L2:** GET безопасен — он ничего не меняет, его можно повторять сколько угодно. POST, PATCH и DELETE **меняют данные**. На рабочем (production) API клиента такие запросы L2 не отправляет без явного согласования — можно, например, случайно создать дубль заказа. В тренажёре — можно всё.

## curl: метод и тело запроса

По умолчанию curl отправляет GET. Другой метод — флагом `-X`, данные — флагом `-d`:

```
curl https://api.shopflow.kz/v1/orders/1043                    # GET
curl -X POST https://api.shopflow.kz/v1/orders/1043/retry      # POST без тела
curl -X POST -H "Content-Type: application/json" \
     -d '{"reason":"customer request"}' \
     https://api.shopflow.kz/v1/orders/1043/retry               # POST с телом
```

- `-X POST` — метод POST;
- `-H "Имя: значение"` — добавить заголовок запроса;
- `-d '...'` — тело запроса (data). Если есть `-d`, curl сам выбирает POST.

## JSON — язык API

**JSON** (JavaScript Object Notation) — текстовый формат данных. Выглядит так:

```json
{
  "id": 1043,
  "status": "failed",
  "total": 279.0,
  "customer": { "email": "lukas@cafe-mitte.de", "country": "DE" },
  "payment": { "provider": "cardpay", "error": "card_declined" }
}
```

- `{ }` — **объект**: набор пар `"ключ": значение`.
- `[ ]` — **массив** (список): `[1, 2, 3]`.
- Значения: строки в кавычках `"failed"`, числа `279.0`, `true`/`false`, `null` (пусто), вложенные объекты и массивы.

Чтобы добраться до поля, пишут путь через точку: `.payment.error` → `"card_declined"`.

## jq — фильтр для JSON

Сервер часто возвращает JSON одной длинной строкой. `jq` делает его читаемым и достаёт нужные поля. Вывод curl передаём в jq через `|`:

```
curl -s URL | jq .                         # красиво отформатировать весь ответ
curl -s URL | jq .status                   # одно поле → "failed"
curl -s URL | jq -r .status                # без кавычек → failed
curl -s URL | jq .payment.error            # вложенное поле
curl -s URL | jq '.items | length'         # сколько элементов в массиве items
curl -s URL | jq '.items[].id'             # id каждого элемента массива
curl -s URL | jq '[.items[] | select(.status == "failed")] | length'
                                           # сколько элементов со статусом failed
```

Разберём последнюю команду по кусочкам:
1. `.items[]` — пройти по каждому элементу массива `items`;
2. `select(.status == "failed")` — оставить только те, где статус `failed`;
3. `[ ... ]` — собрать оставшиеся обратно в массив;
4. `| length` — посчитать, сколько в нём элементов.

Флаг `-s` у curl убирает полосу загрузки, чтобы она не мешала. Фильтр jq с пробелами и `|` бери в одинарные кавычки `'...'`.

## Как это выглядит в тикете

> **Клиент (Berlin Coffee):** Заказ 1043 не оплачен, покупатель говорит, что деньги есть. Повторите оплату!
>
> **L2:** `curl -s https://api.shopflow.kz/v1/orders/1043 | jq .payment` → `"error": "card_declined"` — банк покупателя отклонил карту. Это не ошибка ShopFlow. Отвечаем: «Банк покупателя отклонил платёж (card_declined). Покупателю стоит связаться с банком или оплатить другой картой. После этого можно повторить оплату кнопкой в админке».

Чтобы найти масштаб проблемы, L2 считает: «сколько заказов сегодня в статусе failed и с какой ошибкой» — тот же `jq` с `select`. Если `failed` вдруг много и у всех одна ошибка провайдера — это уже повод для эскалации.

## 🇬🇧 English corner

Термины: *method* — метод, *payload / request body* — тело запроса, *endpoint* — адрес API, *field* — поле, *array* — массив, *object* — объект.

- *Please send a GET request to this endpoint.* — Отправьте GET-запрос на этот адрес.
- *The API returns 405 Method Not Allowed.* — API возвращает 405 «метод не разрешён».
- *The payment was declined by the bank.* — Платёж отклонил банк.
- *Could you share the request body?* — Пришлите, пожалуйста, тело запроса.
