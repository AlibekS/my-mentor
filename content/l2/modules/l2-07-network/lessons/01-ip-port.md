# IP-адрес и порт: куда «стучится» браузер

Любое сетевое соединение — это «**куда**» и «**в какую дверь**». «Куда» — **IP-адрес** компьютера (сервера), «в какую дверь» — **порт** программы на нём. Пример из жизни: IP — адрес дома, порт — номер квартиры. На одном сервере живут сразу несколько программ, и у каждой своя «квартира».

## IP-адрес

IPv4-адрес — четыре числа от 0 до 255 через точку: `10.0.3.21`, `203.0.113.80`.

| Адреса | Что это |
|---|---|
| `127.0.0.1` (`localhost`) | «этот же компьютер» — петлевой адрес (loopback) |
| `10.x.x.x`, `172.16–31.x.x`, `192.168.x.x` | **частные** (внутренние) адреса: офис, дата-центр, домашний роутер. Из интернета напрямую недоступны |
| остальные | **публичные** адреса в интернете |

Запись `10.0.3.21/24` — адрес плюс **маска** (размер сети). Для поддержки маска обычно не важна, отвечая «какой IP», пиши адрес без `/24`.

Посмотреть свой адрес на Linux-сервере:

```
ip a           # все интерфейсы и их адреса (ищи строку inet у eth0)
hostname -I    # только адреса
```

## Порт

Порт — число от 1 до 65535. Запись `адрес:порт` — через двоеточие: `10.0.3.21:443`.

Стандартные порты, которые стоит помнить:

| Порт | Что |
|---|---|
| 22 | SSH — удалённый вход на сервер |
| 53 | DNS |
| 80 | HTTP |
| 443 | HTTPS (почти весь веб) |
| 5432 / 3306 | PostgreSQL / MySQL |
| 6379 | Redis |
| 3000, 8080, 8081 | часто — приложения «за» веб-сервером nginx |

Когда в браузере пишут `https://app.shopflow.io`, порт не указан — браузер сам берёт **443** (для `http://` — 80).

## Кто слушает какой порт: ss

Программа, которая ждёт подключений, **слушает** (listen) порт. Список на сервере:

```
sudo ss -tlnp
```

- `t` — TCP, `l` — только слушающие, `n` — показывать числа (`:443`, а не `:https`), `p` — какой процесс (нужен `sudo`, иначе чужие процессы не видно).

```
State  Local Address:Port   Process
LISTEN 0.0.0.0:443          users:(("nginx",pid=1101,fd=6))
LISTEN 127.0.0.1:3000       users:(("node",pid=2240,fd=6))
```

Главное — **адрес перед портом**:

- `0.0.0.0:443` — порт открыт **на всех адресах** сервера: подключиться можно и снаружи.
- `127.0.0.1:3000` — **только с самого сервера**. Снаружи к этому порту не подключиться никак: так специально делают для приложений, к которым пускают только через nginx.

## Проверить порт: nc

```
nc -zv localhost 3000
# Connection to localhost 3000 port [tcp/*] succeeded!   ← порт открыт
# nc: connect to localhost port 3001 (tcp) failed: Connection refused   ← никто не слушает
```

`-z` — только проверить, ничего не отправляя, `-v` — подробно напечатать результат.

## Как это выглядит в тикете

Клиент пишет: «Я подключаюсь к вашему API на `52.29.10.4:8443`». Ты сразу видишь: IP `52.29.10.4`, порт `8443` — нестандартный. Первый вопрос: правильный ли это порт по документации (обычно API на 443)?

## 🇬🇧 English corner

- *Which IP address and port do you connect to?* — К какому IP-адресу и порту вы подключаетесь?
- *The service listens on port 443.* — Сервис слушает порт 443.
- *The port is open / closed.* — Порт открыт / закрыт.
- *It is only available from localhost.* — Это доступно только с самого сервера.
- *listen* — слушать (ждать подключений); *loopback* — петлевой адрес 127.0.0.1.
