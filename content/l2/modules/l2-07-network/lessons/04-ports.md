# Порты на практике: curl к порту, nc -zv, ss -tlnp на сервере

Сервис «работает» — но клиенты получают ошибку. Очень частая причина: программы **не встретились на порту**. Одна стучится в 8080, другая слушает 8081. Или порт закрыт фаерволом. Сегодня — как это найти за пару минут.

## Как выглядит путь запроса

```
браузер клиента ──443──▶ nginx (0.0.0.0:443) ──8080──▶ приложение reports (127.0.0.1:????)
```

**nginx** — веб-сервер «на входе»: принимает HTTPS от клиентов и передаёт (проксирует) запросы приложению на внутренний порт. Куда передавать, записано в его конфиге строкой `proxy_pass`:

```
location /reports/ {
    proxy_pass http://127.0.0.1:8080;
}
```

Если по этому адресу никто не отвечает, nginx возвращает клиенту **502 Bad Gateway** («шлюз не получил ответа от приложения»).

## curl к конкретному порту

Порт пишут в адресе через двоеточие:

```
curl http://localhost:8080/health
curl: (7) Failed to connect to localhost port 8080 after 0 ms: Couldn't connect to server
```

Ошибка `(7) … Couldn't connect` (Connection refused) — **по этому адресу никто не слушает порт**. Пакет дошёл до компьютера, а тот ответил: «тут никого».

## ss -tlnp — кто реально слушает

```
sudo ss -tlnp
State  Local Address:Port   Process
LISTEN 127.0.0.1:8081       users:(("java",pid=2240,fd=6))
```

Сравни с конфигом: nginx ждёт приложение на 8080, а оно слушает 8081 — вот и 502. Чинят это L3/DevOps (поправить конфиг или порт приложения), а L2 приносит **готовый диагноз**.

## nc -zv — проверка порта на другом сервере

```
nc -zv api.shopflow.io 443
Connection to api.shopflow.io (203.0.113.80) 443 port [tcp/https] succeeded!

nc -zv db.partner.kz 5432
nc: connect to db.partner.kz (91.215.40.12) port 5432 (tcp) timed out: Operation now in progress
```

Три возможных исхода — запомни их, они пригодятся и в следующем уроке:

| Результат | Что значит | Типичная причина |
|---|---|---|
| `succeeded` / `open` | порт открыт, кто-то слушает | всё хорошо на сетевом уровне |
| `Connection refused` | компьютер ответил «здесь никто не слушает» — **быстро** | сервис не запущен или слушает другой порт/адрес |
| `timed out` | ответа нет вообще, ждали до таймаута — **долго** | фаервол молча отбрасывает пакеты, узел выключен, неверный маршрут |

## Как это выглядит в тикете (эскалация)

> Отчёты отдают 502 с 09:10. nginx (`/etc/nginx/conf.d/reports.conf`) проксирует на `127.0.0.1:8080`, там connection refused. Приложение reports (java, pid 2240) слушает `127.0.0.1:8081`, `/health` на 8081 → `{"status":"ok"}`. Похоже, после деплоя сменился порт. Нужна правка конфига nginx или порта приложения.

## 🇬🇧 English corner

- *The reports page shows "502 Bad Gateway".* — Страница отчётов показывает «502 Bad Gateway».
- *Connection refused on port 8080.* — Подключение к порту 8080 отклонено.
- *The connection timed out.* — Время ожидания соединения истекло.
- *The application listens on a different port.* — Приложение слушает другой порт.
- *proxy* — посредник, который передаёт запросы дальше.
