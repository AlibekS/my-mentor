# Считаем и следим: | wc -l, | sort | uniq -c, tail -f

Иногда вопрос не «что случилось у клиента», а «**насколько всё плохо**»: одна ошибка или сотня? У всех или у одного? Прямо сейчас или час назад? Для этого — подсчёт через пайпы и слежение за логом в реальном времени.

## Пайп: собираем команды как конструктор

Знак `|` передаёт вывод левой команды на вход правой:

```
grep ERROR app.log | wc -l
```

1. `grep ERROR app.log` — оставляет строки с ошибками;
2. `wc -l` — считает, сколько строк пришло.

Это то же, что `grep -c ERROR app.log`. Но пайп можно продолжать сколько угодно.

## Достать нужную колонку: awk '{print $N}'

Строка лога делится пробелами на **колонки** (поля):

```
2026-11-04T09:12:03Z  ERROR  [payment]  request_id=…  …
       $1               $2      $3          $4
```

Команда `awk '{print $2}'` печатает **только вторую колонку** каждой строки — уровень:

```
$ awk '{print $2}' app.log | head -3
INFO
INFO
DEBUG
```

`awk` умеет гораздо больше (это целый язык), но L2 хватает этого рецепта. Замени `$2` на `$3` — получишь сервисы.

## Посчитать каждое значение: sort | uniq -c

Рецепт «сколько чего»:

```
awk '{print $2}' app.log | sort | uniq -c
```

1. `awk '{print $2}'` — уровень каждой строки;
2. `sort` — сортирует, одинаковые значения встают **рядом**;
3. `uniq -c` — склеивает одинаковые соседние строки и пишет **сколько их** (c — count).

Результат:

```
     12 DEBUG
     40 ERROR
    310 INFO
     15 WARN
```

> `uniq` склеивает только **соседние** одинаковые строки, поэтому перед ним всегда `sort`.

Хочешь самое частое сверху — добавь `| sort -rn` (по числам, по убыванию).

Тот же рецепт для «у какого сервиса больше всего ошибок»:

```
grep ERROR app.log | awk '{print $3}' | sort | uniq -c | sort -rn
```

## tail -f: следить за логом вживую

`tail -f` (follow — «следовать») показывает конец файла и **ждёт новые строки**: каждая новая запись сразу появляется на экране. Это как смотреть прямой эфир.

```
tail -f /var/log/shop/app.log
tail -f /var/log/shop/app.log | grep u-1042     # следить только за одним клиентом
```

Когда нужно: клиент на связи и говорит «пробую оплатить прямо сейчас» — ты видишь его запрос в момент, когда он нажимает кнопку.

Выйти из `tail -f` — **Ctrl+C**. В тренажёре поток короткий: новые строки «прилетят» и слежение закончится само.

## Частые ошибки

- `uniq -c` без `sort` — одно и то же значение посчитается кусками.
- Забыть, что `grep -c ERROR` считает ошибки **всех** клиентов. Для одного — сначала фильтр по user_id.
- Оставить `tail -f` висеть и думать, что терминал завис. Он просто ждёт строк — нажми Ctrl+C.

## Как это выглядит в тикете

За 10 минут пришло пять тикетов «payment failed». Ты считаешь: `grep ERROR app.log | awk '{print $3}' | sort | uniq -c` → у `[payment]` 60 ошибок, у остальных — единицы. Это не проблема одного клиента, а **инцидент**: эскалируешь в L3 с цифрами — «60 ошибок payment за 10 минут, обычно 2–3».

## 🇬🇧 English corner

- *I'm watching the logs right now.* — Я смотрю логи прямо сейчас.
- *Please try again now.* — Попробуйте, пожалуйста, ещё раз сейчас.
- *It affects many customers.* — Это затрагивает многих клиентов.
- *3-D Secure verification failed* — не пройдена проверка 3-D Secure (подтверждение оплаты в приложении банка или по SMS).
- *did not confirm* — не подтвердил.
