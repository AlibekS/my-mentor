# Из чего состоит строка лога

В модуле про Linux ты уже искал строки в логе через `grep`. Теперь научимся **читать** саму строку: где время, насколько всё плохо, какой сервис её написал и как по ней найти **конкретного клиента** и **конкретный запрос**.

## Строка лога по частям

Вот типичная строка из лога интернет-магазина:

```
2026-11-04T09:12:03Z ERROR [payment] request_id=req-7f3a91 user_id=u-1042 order_id=ORD-58213 msg="Card declined by issuing bank"
```

| Часть | Пример | Что это |
|---|---|---|
| **время** (timestamp) | `2026-11-04T09:12:03Z` | дата и время события; `Z` в конце — время в **UTC** (подробно в следующем уроке) |
| **уровень** (level) | `ERROR` | насколько серьёзно: DEBUG, INFO, WARN, ERROR, FATAL |
| **сервис** (service) | `[payment]` | какая часть системы написала строку: оплата, корзина, вход… |
| **идентификаторы** (IDs) | `request_id=…`, `user_id=…`, `order_id=…` | «ярлыки», по которым ищут клиента, заказ или запрос |
| **сообщение** (message) | `msg="Card declined by issuing bank"` | что случилось — обычно по-английски |

Формат у разных компаний немного разный, но эти части есть почти всегда. Иногда логи пишут в формате JSON (`{"level":"error","msg":"…"}`) — части те же, просто в фигурных скобках.

## Три главных идентификатора

- **user_id** — кто: конкретный пользователь (клиент). По нему видно **всё**, что делал клиент.
- **order_id** — какой заказ. Его клиент обычно пишет в тикете сам: «my order ORD-58213».
- **request_id** (иногда `trace_id`, `correlation_id`) — **один запрос** клиента. Нажал «Оплатить» → запрос получил id → каждый сервис, который его обрабатывал, пишет в лог **тот же** request_id.

Поэтому request_id — самая полезная улика: по нему собирается **вся цепочка** одного действия клиента через разные сервисы.

```
09:12:01Z INFO  [api]      request_id=req-7f3a91 … msg="POST /api/checkout"
09:12:02Z INFO  [checkout] request_id=req-7f3a91 … msg="Order created"
09:12:03Z ERROR [payment]  request_id=req-7f3a91 … msg="Card declined by issuing bank"
```

Сверху вниз читается история: клиент нажал «оформить», заказ создался, оплата отклонена банком.

## Как искать

Всё тот же `grep`:

```
grep req-7f3a91 /var/log/shop/app.log        # вся история одного запроса
grep user_id=u-1042 /var/log/shop/app.log    # всё про клиента u-1042
grep ORD-58213 /var/log/shop/app.log         # всё про заказ
```

Совет: ищи с префиксом (`user_id=u-1042`), если номер короткий — так не поймаешь случайно `u-10420`.

## Частые ошибки

- Читать сообщение без времени: ошибка «Card declined» вчерашняя — не про сегодняшний тикет.
- Путать сервис и уровень: `[payment]` — кто написал, `ERROR` — насколько плохо.
- Искать только по user_id и не заметить, что у клиента было несколько запросов. Нашёл нужную строку — бери её request_id и смотри цепочку целиком.

## Как это выглядит в тикете

Клиент: «Order ORD-58213 — payment failed». Ты: `grep ORD-58213 app.log` → находишь строку с ERROR, берёшь из неё `request_id` → `grep req-… app.log` → видишь всю цепочку. В тикет — 2–3 ключевые строки и вывод: «оплату отклонил банк клиента (Card declined by issuing bank), со стороны магазина ошибки нет».

## 🇬🇧 English corner

- *Card declined by issuing bank* — карта отклонена банком-эмитентом (банком, который выпустил карту).
- *Order created* — заказ создан.
- *Payment captured* — оплата списана (успешно).
- *Could you send me your order number?* — Пришлите, пожалуйста, номер заказа.
- *I can see the error in our logs.* — Я вижу эту ошибку в наших логах.
