# Ошибки одного клиента: user_id, order_id, request_id

Типичный тикет L2 — про **одного** клиента: «у меня не проходит оплата», «заказ завис». В логе за час — тысячи строк от сотен людей. Задача — быстро отфильтровать **только этого клиента**, увидеть его ошибки и собрать доказательства. Для этого хватает `grep` и трёх флагов: `-i`, `-c`, `-v`.

## Шаг 1. Найти зацепку в тикете

Что обычно есть в тикете:

| Что пишет клиент | Что искать в логе |
|---|---|
| номер заказа *«order ORD-60411»* | `order_id=ORD-60411` |
| email *«my email is Dana.K@Example.com»* | `email=…` — регистр может отличаться! |
| скриншот с кодом ошибки | текст ошибки, request_id на экране |
| «ваш сайт не работает» | ничего — **спроси** номер заказа или email |

## Шаг 2. Перейти от зацепки к user_id

Email или номер заказа часто есть только в **одной** строке (например, при входе). Находишь её → берёшь оттуда `user_id` → дальше ищешь по нему.

### grep -i: регистр не важен

Клиент написал email с большими буквами, а в логе он маленькими. Обычный `grep` не найдёт. Флаг `-i` (ignore case):

```
grep -i Dana.K@Example.com app.log
```

## Шаг 3. Все строки клиента и его ошибки

```
grep user_id=u-3150 app.log                  # всё, что делал клиент
grep user_id=u-3150 app.log | grep ERROR     # только его ошибки
grep user_id=u-3150 app.log | grep -c ERROR  # сколько у него ошибок
```

Здесь два `grep` соединены **пайпом** `|`: первый оставляет строки клиента, второй — из них только ошибки. Фильтры можно ставить друг за другом сколько угодно.

## grep -v: убрать лишнее

`-v` (invert — «наоборот») показывает строки, где слова **нет**. Удобно, чтобы выкинуть шум:

```
grep user_id=u-3150 app.log | grep -v DEBUG          # клиент без отладочных строк
grep user_id=u-3150 app.log | grep -v DEBUG | grep -v INFO   # только WARN и ERROR
```

## Шаг 4. Цепочка запроса

Нашёл ошибку — возьми её `request_id` и выведи **весь запрос**: так видно, что было до ошибки в других сервисах.

```
grep req-9e04c7 app.log
```

## Сводка флагов

| Флаг | Смысл | Пример |
|---|---|---|
| `-i` | без учёта регистра | `grep -i dana.k@example.com` |
| `-c` | посчитать строки | `grep -c ERROR` |
| `-v` | строки **без** шаблона | `grep -v DEBUG` |
| `-n` | номер строки | `grep -n ORD-60411` |

## Частые ошибки

- Искать email как есть и решить «в логах клиента нет». Пробуй `-i`.
- Посчитать ошибки **всех** клиентов вместо одного: сначала фильтр по user_id, потом `grep -c ERROR`.
- Искать по короткому номеру без префикса: `grep 315` поймает и `u-3150`, и `ORD-63150`, и `315 ms`.

## Как это выглядит в тикете

*«Hi, I can't log in and my order ORD-60411 is not paid. My email is Dana.K@Example.com»*. Ты: `grep -i` по email → `user_id=u-3150`; `grep user_id=u-3150 app.log | grep -v DEBUG` → видишь 3 неудачных входа и ошибку оплаты; берёшь request_id ошибки → вся цепочка. В тикет: «у клиента u-3150 с 09:05 до 09:12 UTC три Invalid password, затем оплата ORD-60411 отклонена (Insufficient funds), request_id …».

## 🇬🇧 English corner

- *Could you please share your order number and email?* — Пришлите, пожалуйста, номер заказа и email.
- *I found your request in our logs.* — Я нашёл ваш запрос в наших логах.
- *Invalid password attempt* — попытка входа с неверным паролем.
- *Your account is temporarily locked.* — Ваш аккаунт временно заблокирован.
- *The order is still pending.* — Заказ всё ещё в ожидании (не оплачен).
