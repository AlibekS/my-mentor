# 👹 Босс модуля: «Утренняя очередь L2»

**Среда, 09:35 UTC.** Ты заступаешь на смену L2 в ShopFlow. Коллега из ночной смены оставил записку: «В очереди 5 новых тикетов, я не успел разобрать. Что-то странное с оплатой — пишут несколько магазинов».

Открываешь очередь — и сразу понимаешь: сегодня скучно не будет.

## Что у тебя есть

```
~/queue/             тикеты (по одному файлу на тикет)
~/kb/priority.md     матрица приоритетов
~/kb/sla.md          сроки SLA
/var/log/shopflow/payments.log   лог платёжного сервиса
```

## Твоя цепочка действий как L2

1. **Triage.** Понять, сколько тикетов про одну и ту же проблему. Если несколько магазинов пишут об одном — это не пять отдельных проблем, а один **инцидент**.
2. **Приоритет.** По матрице: ключевая функция? много клиентов? есть обход?
3. **SLA.** От какого тикета считать срок первого ответа и до какого времени ответить. Напомню: считать от **самого раннего** тикета — клиент, написавший первым, ждёт дольше всех.
4. **Факты.** Найти в логе платёжного сервиса, что именно происходит: код ошибки, с какого времени, примеры request id.
5. **Эскалация.** Это массовая проблема с оплатой — без правки на стороне платформы или провайдера её не решить. Написать эскалацию в L3 так, чтобы дежурный инженер начал работать сразу.

## Напоминалка по командам

```
ls ~/queue                                   # список тикетов
cat ~/queue/ZD-2501.txt                      # открыть тикет
grep "Category: payments" ~/queue/*          # найти строку во всех тикетах
grep -l "текст" ~/queue/* | wc -l            # сколько файлов содержат текст
grep ERROR /var/log/shopflow/payments.log    # строки с ошибками
grep -c ERROR /var/log/shopflow/payments.log # сколько их
head -3 файл                                 # первые 3 строки
```

## Подсказка про время

Все тикеты и логи — в UTC. Самый ранний тикет — тот, у кого строка `Created:` меньше. P1 по SLA — **30 минут** на первый ответ.

Удачи! После этого босса ты умеешь главное, что отличает L2 от L1: не просто отвечать, а **сортировать, считать сроки, находить факты и передавать дальше так, чтобы не вернули**.

## 🇬🇧 English corner

Термины: *incident* — инцидент (авария, затронувшая клиентов), *on-call engineer* — дежурный инженер, *payment provider* — платёжный провайдер, *outage* — простой, недоступность.

- *Several customers report the same issue.* — Несколько клиентов сообщают об одной и той же проблеме.
- *Payments have been failing since 09:04 UTC.* — Платежи не проходят с 09:04 UTC.
- *I have linked the tickets to the incident.* — Я связал тикеты с инцидентом.
- *Please treat this as P1.* — Пожалуйста, рассматривайте это как P1.
