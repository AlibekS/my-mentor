# Таблица, строка, столбец: первый SELECT

Почти у любого SaaS-продукта данные лежат в **базе данных** (database, БД): клиенты, заказы, платежи, тикеты. Когда клиент пишет «у меня пропал заказ», L2 часто может сам заглянуть в базу и проверить факты — вместо того чтобы сразу эскалировать в L3. Для этого нужен **SQL** (Structured Query Language) — язык запросов к базе.

Хорошая новость: для работы L2 хватает небольшой части SQL — **запросов на чтение**. Ты ничего не меняешь в базе, только смотришь.

## Таблица — это как лист Excel

База состоит из **таблиц** (table). Таблица похожа на лист Excel:

| id | email | name | country | plan |
|---|---|---|---|---|
| 1 | aigerim.nurlanova@mail.kz | Aigerim Nurlanova | KZ | pro |
| 2 | dias.bekov@gmail.com | Dias Bekov | KZ | free |
| 3 | anna.schmidt@web.de | Anna Schmidt | DE | business |

- **Строка** (row, запись) — один объект: один клиент, один заказ, один платёж.
- **Столбец** (column, поле) — одно свойство: email, страна, тариф. У всех строк набор столбцов одинаковый.
- **id** — уникальный номер строки, **первичный ключ** (primary key). Двух клиентов с одним id не бывает. По id удобно искать: «заказ 1057», «платёж 5060».

## Наша база: интернет-магазин Tulpar Store

| Таблица | Что внутри |
|---|---|
| `customers` | клиенты: email, имя, страна, тариф (plan) |
| `orders` | заказы: какой клиент (`customer_id`), статус (`paid`, `unpaid`, `cancelled`, `refunded`), сумма (`total`), время |
| `payments` | платежи: по какому заказу (`order_id`), статус (`succeeded`, `failed`, `pending`, `refunded`), способ, код ошибки |
| `support_tickets` | тикеты поддержки: тема, статус, приоритет, исполнитель (`assignee`) |

Схема базы — под SQL-консолью справа (раскрывается). Клик по таблице вставит готовый запрос `SELECT * … LIMIT 10`. Время в базе — в **UTC**, «сегодня» — 5 ноября 2026.

## Первый запрос: SELECT … FROM …

```sql
SELECT * FROM customers;
```

Читается почти как по-английски: «выбери (SELECT) всё (`*`) из (FROM) таблицы customers».

- `SELECT` — **какие столбцы** показать. `*` — все столбцы.
- `FROM` — **из какой таблицы**.
- `;` — конец запроса (в консоли можно не ставить, но это хорошая привычка).

Нужны не все столбцы, а только некоторые — перечисли их через запятую:

```sql
SELECT email, plan FROM customers;
```

Столбцы в ответе идут **в том порядке, в котором ты их написал**. В заданиях порядок столбцов важен — пиши их так, как в формулировке.

## LIMIT — «покажи только первые N строк»

```sql
SELECT * FROM payments LIMIT 5;
```

На работе таблицы бывают огромными — миллионы строк. Запрос без ограничения может долго выполняться и нагружать базу. Правило: **на незнакомой таблице всегда начинай с `LIMIT`** — чтобы посмотреть, какие там столбцы и данные.

## Пара мелочей

- Ключевые слова можно писать маленькими буквами: `select * from customers` — тоже работает. Большими пишут для читаемости.
- Переносы строк не важны: запрос можно написать в одну строку или в несколько.
- Ошибка в имени таблицы или столбца → сообщение `no such table` / `no such column`. Проверь написание по схеме.

## Только чтение

На проде у L2 обычно доступ **только на чтение** (read-only), часто к копии базы (read replica). Команды, которые меняют данные (`UPDATE`, `DELETE`, `INSERT`), — не наша работа: если данные нужно исправить, это эскалация в L3 с фактами.

## Как это выглядит в работе

Тикет: «Hi, I can't see my order». Первое, что ты делаешь, — смотришь, что вообще есть в таблицах:

```sql
SELECT * FROM orders LIMIT 10;
```

Видишь столбцы `id, customer_id, status, total, created_at` — теперь понятно, по каким полям искать. В следующем уроке научимся находить **конкретного** клиента и его заказы.

## 🇬🇧 English corner

- *table / row / column* — таблица / строка / столбец
- *Could you check the database?* — Можешь проверить в базе?
- *I ran a query.* — Я выполнил запрос.
- *read-only access* — доступ только на чтение
