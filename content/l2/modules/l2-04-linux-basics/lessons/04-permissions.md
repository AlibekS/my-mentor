# Права доступа и sudo: читаем ls -l

Рано или поздно ты попробуешь открыть файл и получишь **Permission denied**. Это не поломка: Linux просто не разрешает твоему пользователю читать этот файл. В этом уроке научимся понимать, **кому что можно**, и пользоваться `sudo` — аккуратно и только для чтения. Менять права (`chmod`, `chown`) — задача L3, здесь мы их только читаем.

## ls -l: подробный список

```
$ ls -l /etc/shop
-rw-r--r-- 1 root root  142 Nov  4 09:00 app.conf
-rw------- 1 root root   64 Nov  4 09:00 secrets.env
```

Разберём строку про `app.conf` слева направо:

| Часть | Значение |
|---|---|
| `-` | тип: `-` — обычный файл, `d` — каталог (directory) |
| `rw-r--r--` | **права** (permissions) — 9 символов, о них ниже |
| `1` | число ссылок — можно не обращать внимания |
| `root` | **владелец** (owner) — пользователь, которому принадлежит файл |
| `root` | **группа** (group) — группа пользователей с особыми правами |
| `142` | размер в байтах |
| `Nov  4 09:00` | дата и время последнего изменения |
| `app.conf` | имя |

## Девять символов прав

Права делятся на **три тройки**:

```
 rw-    r--    r--
владелец группа остальные
 (user) (group) (others)
```

В каждой тройке три позиции:

| Буква | Значение | Для файла |
|---|---|---|
| `r` | read | можно читать |
| `w` | write | можно изменять |
| `x` | execute | можно запускать (программа, скрипт) |
| `-` | — | права нет |

Читаем `rw-r--r--`: владелец читает и пишет, группа только читает, остальные только читают.
А `rw-------`: владелец читает и пишет, **всем остальным — ничего**. Так защищают секреты: пароли, ключи.

## Permission denied

```
$ cat /etc/shop/secrets.env
cat: /etc/shop/secrets.env: Permission denied
```

*Permission denied* — «доступ запрещён». Ты пользователь `alibek`, а файл может читать только `root`. Чтобы понять почему — посмотри `ls -l` на этот файл.

## Кто я и в каких я группах

```
$ whoami
alibek
$ id
uid=1000(alibek) gid=1000(alibek) groups=1000(alibek),4(adm),27(sudo)
```

Если ты в группе файла — тебе действуют права **группы** (средняя тройка). Иначе — права «остальных».

## sudo — выполнить от имени root

**root** — главный администратор, ему можно всё. `sudo` (super user do) выполняет **одну команду** от имени root:

```
$ sudo tail -n 5 /var/log/shop/audit.log
```

Правила для L2:

- `sudo` выдают не всем. Если выдали — используй **для чтения** того, что нужно по тикету (лог, статус).
- Ничего не меняй и не удаляй через `sudo` без runbook (инструкции) или согласования с L3.
- Секреты (пароли, ключи из `secrets.env`) не копируй в тикеты и чаты.

## Частые ошибки

- Увидев Permission denied, сразу просить «дайте мне root». Сначала разберись через `ls -l`: может, нужный лог лежит рядом и он читается.
- Путать владельца и группу: третья колонка — владелец, четвёртая — группа.
- Писать `sudo` перед всеми командами «на всякий случай». Так легко случайно что-то сломать.

## Как это выглядит в тикете

L3 просит: «пришли последние строки audit.log». Ты пробуешь `tail` — Permission denied. Смотришь `ls -l`: файл `rw------- root`. Если у тебя есть `sudo` — `sudo tail -n 20 /var/log/shop/audit.log`. Если нет — честно пишешь в тикете: «audit.log доступен только root (права 600), прочитать не могу, нужна помощь L3».

## 🇬🇧 English corner

- *Permission denied* — Доступ запрещён (нет прав).
- *I don't have access to this file.* — У меня нет доступа к этому файлу.
- *The file is readable only by root.* — Файл может читать только root.
- *owner / group / others* — владелец / группа / остальные.
- *Could you check it with sudo?* — Можешь проверить через sudo?
