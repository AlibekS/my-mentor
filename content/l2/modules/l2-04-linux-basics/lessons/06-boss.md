# 👹 Босс модуля: «Клиенты жалуются, что сайт не открывается»

**Среда, 02:20 по времени сервера.** В Zendesk за десять минут пришло пять тикетов: *«Your website is not working»*, *«I get 502 Bad Gateway»*, *«Не могу зайти в магазин»*. Ты — дежурный L2. Доступ к серверу `shop-web-01` у тебя есть, `sudo` — тоже, но **чинить ничего не нужно**: твоя задача — быстро подтвердить проблему, найти, что сломалось, и собрать факты для L3.

## Что известно

- Сайт: `https://shop.example.com`.
- На сервере работают `nginx` (принимает запросы клиентов) и приложение `shop-app` (магазин). nginx передаёт запросы приложению.
- Если приложение не отвечает, nginx возвращает клиенту **502 Bad Gateway** («шлюз получил плохой ответ»).

## Твой план

1. **Подтвердить** проблему: какой HTTP-код отдаёт сайт (`curl -I` из модуля про веб).
2. **Найти** упавший сервис: `systemctl --failed`, `systemctl status …`.
3. **Прочитать** причину в журнале сервиса: `journalctl -u … -n 20`. Сообщение будет на английском.
4. **Записать время**, когда начались ошибки: лог nginx `/var/log/nginx/error.log`.
5. **Сохранить** факты в файл `~/escalation.txt` — его заберёт L3.

## Как сохранить находки в файл

Вывод любой команды можно записать в файл знаком `>` (перезаписать) или дописать знаком `>>`:

```
systemctl status shop-app > ~/escalation.txt          # создать файл и записать статус
journalctl -u shop-app -n 20 >> ~/escalation.txt      # дописать журнал в конец
echo "Сервер: shop-web-01" >> ~/escalation.txt        # дописать свою строку
cat ~/escalation.txt                                  # проверить, что получилось
```

`echo "текст"` просто печатает текст — а с `>>` дописывает его в файл.

## Хорошая эскалация в L3 содержит

- **где**: сервер (`hostname`);
- **что**: какой сервис и в каком он состоянии;
- **ошибку**: точную строку из журнала;
- **когда**: время начала по логам (и в каком часовом поясе — время сервера);
- **что ты уже сделал**: «ничего не перезапускал».

Удачи! Не торопись: все команды здесь только **читают** — кроме записи твоего файла с фактами.

## 🇬🇧 English corner

- *502 Bad Gateway* — «плохой шлюз»: прокси не получил ответа от приложения.
- *We are aware of the issue and working on it.* — Мы знаем о проблеме и работаем над ней.
- *The website is down.* — Сайт не работает.
- *connection refused* — в соединении отказано (на том адресе никто не принимает подключения).
- *Escalated to L3 with logs attached.* — Эскалировано в L3, логи приложены.
