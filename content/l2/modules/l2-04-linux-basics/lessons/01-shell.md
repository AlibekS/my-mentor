# Сервер, терминал и навигация: pwd, ls, cd

Ты уже умеешь работать в Zendesk и Jira. Но иногда, чтобы ответить клиенту, нужно заглянуть **на сам сервер**: посмотреть лог, проверить, работает ли сервис. Почти все серверы SaaS-компаний работают на **Linux**, и общаются с ними через **терминал** — текстом, без мышки. Звучит страшно, но на старте хватит десятка команд. Начнём с трёх: где я, что здесь лежит, как перейти в другое место.

## Что такое сервер и терминал

- **Сервер** — это компьютер в дата-центре или облаке, на котором работает продукт: сайт магазина, API, база данных. Экрана у него нет.
- Чтобы им управлять, инженер подключается по **SSH** (Secure Shell — защищённое подключение) и получает **терминал** — окно, куда пишутся команды.
- Программа, которая читает твои команды и выполняет их, называется **оболочка** (shell). Чаще всего это `bash`.

В тренажёре справа — такой же терминал. Ты пишешь команду, нажимаешь Enter — сервер отвечает текстом.

## Приглашение (prompt): кто я и где я

Перед курсором терминал показывает **приглашение**:

```
alibek@shop-web-01:~$
```

Разберём по частям:

| Часть | Что значит |
|---|---|
| `alibek` | твой пользователь |
| `@shop-web-01` | имя сервера (hostname) — **всегда сверяй**, тот ли это сервер |
| `~` | текущий каталог; `~` — твой домашний каталог (`/home/alibek`) |
| `$` | ты обычный пользователь; `#` — ты **root** (администратор), будь очень осторожен |

Имя сервера можно узнать и командой:

```
$ hostname
shop-web-01
```

## pwd — где я сейчас

`pwd` (print working directory — «покажи рабочий каталог») печатает полный путь к каталогу, в котором ты находишься:

```
$ pwd
/home/alibek
```

**Каталог** (directory) — то же самое, что папка в Windows.

## ls — что здесь лежит

`ls` (list) показывает содержимое каталога:

```
$ ls /var/log/shop
app.log  app.log.1  payments.log
```

- `ls` без пути — содержимое **текущего** каталога.
- `ls /var/log/shop` — содержимое указанного каталога, переходить туда не нужно.
- `ls -l` — подробно (права, владелец, размер, дата) — разберём в уроке про права.
- `ls -a` — показать и **скрытые** файлы (их имена начинаются с точки, например `.env`).

## cd — перейти в другой каталог

`cd` (change directory) — «перейти»:

```
$ cd /var/log/shop
alibek@shop-web-01:/var/log/shop$
```

Приглашение сразу изменилось: теперь вместо `~` там `/var/log/shop`.

## Пути: абсолютные и относительные

Путь — это «адрес» файла или каталога. Каталоги в Linux вложены друг в друга, а самый верхний называется **корень** и пишется как `/`.

- **Абсолютный путь** начинается с `/` и работает **откуда угодно**: `/var/log/nginx`.
- **Относительный путь** считается **от текущего каталога**: если ты в `/var/log`, то `nginx` — это `/var/log/nginx`.

Специальные обозначения:

| Запись | Значение |
|---|---|
| `.` | текущий каталог |
| `..` | каталог уровнем выше (родительский) |
| `~` | твой домашний каталог |

Примеры:

```
cd /var/log        # абсолютный путь — из любого места
cd nginx           # относительный: из /var/log попадём в /var/log/nginx
cd ..              # на уровень выше: снова /var/log
cd ../shop         # выше и в соседний каталог: /var/log/shop
cd                 # без аргументов — домой (/home/alibek)
```

> Если сомневаешься — используй абсолютный путь. Он длиннее, но не зависит от того, где ты стоишь.

## Где что лежит на сервере

| Каталог | Что там | Когда нужен L2 |
|---|---|---|
| `/var/log` | логи (журналы событий) | почти всегда: «что случилось?» |
| `/etc` | настройки (конфиги) | посмотреть адрес, порт, параметр |
| `/opt` | установленные приложения | какая версия продукта стоит |
| `/home` | домашние каталоги пользователей | твои заметки и файлы |

## Частые ошибки

- **No such file or directory** — «нет такого файла или каталога». Чаще всего — опечатка в пути (`/var/logs` вместо `/var/log`). Проверь путь через `ls`.
- Забыть, что относительный путь зависит от текущего каталога. Сначала `pwd`, потом `cd`.
- Регистр букв важен: `Shop` и `shop` — разные каталоги.

## Как это выглядит в тикете

Клиент пишет: «сайт иногда отдаёт ошибку». Ты заходишь на сервер и **сначала** проверяешь, где ты: `hostname` (тот ли сервер), `pwd`. Потом идёшь к логам: `cd /var/log/shop`, `ls`. В заметке к тикету пишешь: «Проверил сервер shop-web-01, логи в /var/log/shop» — L3 сразу знает, куда смотреть.

## 🇬🇧 English corner

- *No such file or directory* — Нет такого файла или каталога.
- *Which server did you check?* — На каком сервере ты проверял?
- *The logs are in /var/log/shop.* — Логи лежат в /var/log/shop.
- *I'm logged in to shop-web-01.* — Я зашёл на shop-web-01.
- *current directory / home directory* — текущий каталог / домашний каталог.
