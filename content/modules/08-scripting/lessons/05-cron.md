# Расписание: cron и systemd timers

Скрипт проверки полезен, когда он запускается **сам**: каждые 5 минут, ночью, раз в неделю.

## Формат crontab

```
┌ минута (0–59)
│ ┌ час (0–23)
│ │ ┌ день месяца (1–31)
│ │ │ ┌ месяц (1–12)
│ │ │ │ ┌ день недели (0–7, 0 и 7 = воскресенье)
│ │ │ │ │
*/5 * * * *  /opt/scripts/health.sh >> /var/log/health.log 2>&1
0 3 * * *    /opt/scripts/backup.sh
30 9 * * 1-5 /opt/scripts/report.sh        # будни в 09:30
0 */4 * * *  /opt/scripts/cleanup.sh       # каждые 4 часа
@reboot      /opt/scripts/on_boot.sh
```

`*` — любое значение, `*/5` — каждые 5, `1-5` — диапазон, `1,15` — список. Проверять расписания удобно на crontab.guru.

## Команды

```
crontab -l          # показать свои задачи
crontab -e          # редактировать (в тренажёре: nano файл → crontab файл)
crontab mycron      # установить из файла
crontab -r          # удалить все свои задачи (осторожно!)
sudo crontab -u app -l   # задачи другого пользователя
ls /etc/cron.d/          # системные задачи
```

## Подводные камни cron

- **Другое окружение**: у cron минимальный `PATH` и нет твоих переменных → пиши **полные пути** (`/usr/bin/curl`) или задавай `PATH=` в начале crontab.
- **Вывод теряется** (или уходит в локальную почту) → перенаправляй: `>> /var/log/job.log 2>&1`.
- **Время** — по часовому поясу сервера (часто UTC!).
- **Наложение запусков**: если задача длиннее интервала — используй `flock -n /tmp/job.lock команда`.

## systemd timers — современная альтернатива

Пара `job.service` + `job.timer` (`OnCalendar=*:0/5`). Плюсы: логи в `journalctl -u job`, зависимости, `Persistent=true` (догонит пропущенный запуск). `systemctl list-timers` — все таймеры и когда сработают.

## Как это выглядит на реальной работе L3

«Ночной бэкап не делается уже неделю». Ты: `sudo crontab -u backup -l` — задача есть; ручной запуск работает; в логе cron `pg_dump: command not found` — в cron другой PATH. Фикс — полный путь `/usr/bin/pg_dump` и алерт, если файла бэкапа за сутки нет.

## Типичные ошибки

- Путать порядок полей (минуты первые!).
- `* 3 * * *` вместо `0 3 * * *` — запуск каждую минуту с 03:00 до 03:59.
- Нет перенаправления вывода — ошибки задачи никто не увидит.
