# 👹 Босс модуля: «Чек-лист дежурного в один скрипт»

После прошлого инцидента руководитель поддержки просит: «Хватит проверять руками. Нужен скрипт, который дежурный L2 запускает одной командой, и который же каждые 5 минут гоняет cron».

Требования к `~/healthcheck.sh`:

1. Проверяет, что сервисы **nginx** и **shop** в статусе active.
2. Проверяет, что диск `/` занят **меньше 85%**.
3. Проверяет, что `https://shop.kz/health` отвечает **200**.
4. Для каждой проверки печатает строку `OK: …` или `FAIL: …` (что именно проверялось — на твоё усмотрение, но начало строки строго `OK:` / `FAIL:`).
5. Завершается с кодом **0**, если все проверки прошли, и **1**, если хотя бы одна упала (не останавливаясь на первой ошибке — дежурному нужен полный список).

Затем — запустить, понять, что сломано, починить и поставить скрипт в cron.

Скелет, если нужно:

```bash
#!/usr/bin/env bash
FAILED=0
check() {          # check "описание" команда...
  local name="$1"; shift
  if "$@" > /dev/null 2>&1; then echo "OK: $name"; else echo "FAIL: $name"; FAILED=1; fi
}
check "nginx active" systemctl is-active nginx
# check "shop active" ...
# USED=$(df / | awk 'NR==2 {print $5}' | tr -d '%')
# check "disk $USED%" [ "$USED" -lt 85 ]
# check "http 200" curl -sf https://shop.kz/health
exit $FAILED
```

> `"$@"` — все аргументы функции после `shift`, то есть сама команда проверки со своими аргументами. Можно обойтись и без функции: те же проверки по очереди через `if … then … fi`.
