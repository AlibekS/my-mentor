# Переменные, кавычки и подстановки

Скрипт — это те же команды, которые ты вводишь руками, только записанные в файл. Начнём с кирпичиков, которые работают и в терминале.

## Переменные

```bash
HOST=web-01                 # без пробелов вокруг =
echo "Сервер: $HOST"
echo "Сервер: ${HOST}-backup"   # фигурные скобки — граница имени
LOG=${LOG_FILE:-/var/log/app.log}   # значение по умолчанию, если переменная пустая
```

> `HOST = web-01` (с пробелами) — ошибка: bash ищет команду `HOST`.

Переменные окружения (`$HOME`, `$USER`, `$PATH`) доступны всем программам; свою переменную делают доступной дочерним процессам через `export`.

## Кавычки

| Запись | Что происходит |
|---|---|
| `"текст $VAR"` | переменные и `$(...)` **раскрываются** |
| `'текст $VAR'` | всё буквально, ничего не раскрывается |
| без кавычек | раскрывается + делится по пробелам и `*` превращается в список файлов |

Правило: **переменные всегда в двойных кавычках** — `"$FILE"`. Иначе имя файла с пробелом сломает скрипт.

## Подстановка команды $(...)

```bash
COUNT=$(grep -c ERROR /var/log/app.log)
echo "Ошибок: $COUNT"
echo "Сегодня $(date +%F), сервер $(hostname)"
```

Старый синтаксис — обратные кавычки `` `cmd` `` — встречается в старых скриптах, но `$(...)` читаемее и вкладывается.

## Арифметика $((...))

```bash
TOTAL=$((OK + FAIL))
PCT=$((FAIL * 100 / TOTAL))      # только целые числа!
i=$((i + 1))
```

Для дробных — `awk` или `bc`.

## printf вместо echo для отчётов

```bash
printf "%-10s %5s\n" "host" "errors"
printf "%-10s %5d\n" "web-01" 12
```

## Как это выглядит на реальной работе L3

Вместо того чтобы пять раз руками набирать `grep -c ERROR …` по разным логам и складывать в уме, L3 пишет однострочник с переменными и `$(...)` — и копирует результат прямо в тикет.

## Типичные ошибки

- Пробелы вокруг `=`.
- Одинарные кавычки там, где нужна подстановка: `echo '$HOST'` выведет `$HOST`.
- `$(( 10 / 3 ))` = 3, а не 3.33.
