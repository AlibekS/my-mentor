# Просмотр файлов: cat, less, head, tail, wc

Логи бывают по 10 ГБ. Открыть такой файл в редакторе — положить сервер. L3 смотрит файлы **порциями**.

## cat — вывести целиком

```
cat /etc/hostname
cat -n config.yml     # с номерами строк
```

Подходит для **маленьких** файлов: конфиги, заметки. Для лога на миллион строк — нет.

## less — листать

```
less /var/log/syslog
```

Внутри `less`: `пробел` / `b` — страница вперёд/назад, `/ошибка` — поиск вперёд, `n` — следующее совпадение, `G` — в конец файла, `g` — в начало, `q` — выход. Плюс: `less +F файл` — режим слежения, как `tail -f`.

> В тренажёре `less` упрощён: показывает первые 40 строк. Для поиска используй `grep` (модуль «Логи»).

## head и tail — начало и конец

```
head config.yml           # первые 10 строк
head -n 3 config.yml      # первые 3
tail /var/log/app.log     # последние 10
tail -n 50 /var/log/app.log
tail -f /var/log/app.log  # следить за новыми строками (выход Ctrl+C)
tail -n +100 file         # с 100-й строки до конца
```

`tail -f` — главный инструмент во время инцидента: перезапустил сервис и **смотришь вживую**, что он пишет.

## wc — посчитать

```
wc -l access.log    # сколько строк
wc -c file          # сколько байт
```

## Пайп (|) — первое знакомство

Вывод одной команды можно передать на вход другой:

```
cat access.log | wc -l
head -n 100 access.log | tail -n 1    # ровно 100-я строка
```

Подробно пайпы — в модуле «Логи и поиск».

## Как это выглядит на реальной работе L3

Клиент пишет: «с 10 утра ошибки». Ты: `tail -n 100 /var/log/app/app.log` — что происходит сейчас; `head -n 5` — с какого времени начинается файл (вдруг ротация была ночью и нужный период в `app.log.1`); `wc -l` — объём, чтобы понять, сколько событий за день.

## Типичные ошибки

- `cat` огромного файла — терминал зависнет, а через SSH ещё и канал забьётся.
- Забыть, что логи ротируются: вчерашние строки в `app.log.1` или `app.log.2.gz`.
- `tail -f` на файл, который уже ротировали: пиши `tail -F` (следит по имени).
