# Поиск файлов: find

«Где лежит конфиг?», «что съело диск?», «какие файлы поменялись после релиза?» — на всё это отвечает `find`.

## Синтаксис

```
find <где искать> <условия>
```

### По имени

```
find /etc -name "nginx.conf"
find /var/log -name "*.log"       # шаблон — в кавычках!
find / -iname "*readme*"          # без учёта регистра
```

> Кавычки вокруг `"*.log"` обязательны: иначе оболочка сама раскроет `*` в текущем каталоге, и `find` получит не то.

### По типу

```
find /opt -type f      # только файлы
find /opt -type d      # только каталоги
```

### По размеру

```
find /var -type f -size +100M     # больше 100 МБ
find /tmp -size -1k               # меньше 1 КБ
find /var/log -empty              # пустые
```

Суффиксы: `k` — КБ, `M` — МБ, `G` — ГБ, `c` — байты.

### По времени изменения

```
find /etc -mtime -1        # изменены менее суток назад
find /var/log -mtime +30   # старше 30 дней
find /opt/app -mmin -60    # изменены за последний час
```

`-1` = «меньше 1», `+30` = «больше 30», без знака = «ровно».

### Комбинации и глубина

```
find /var/log -name "*.log" -size +50M -mtime -7
find /etc -maxdepth 1 -name "*.conf"
find /home -user alibek
```

Условия через пробел работают как **И**.

## Ошибки «Permission denied»

От обычного пользователя `find /` насыпет много `Permission denied`. Это не ошибка поиска — просто нет прав читать какие-то каталоги. Убрать шум: `find / -name x 2>/dev/null` (ошибки — в «чёрную дыру»), или искать через `sudo`.

## Как это выглядит на реальной работе L3

Алерт: «диск / заполнен на 95%». Первые шаги:
```
find / -xdev -type f -size +500M 2>/dev/null
```
Находишь `/var/lib/app/dumps/heap-2026-11-03.hprof` на 6 ГБ — кто-то снимал дамп памяти и забыл удалить.

После релиза что-то сломалось? «Какие конфиги менялись за последний день»:
```
find /etc /opt/app -mtime -1 -type f
```

## Типичные ошибки

- Шаблон без кавычек.
- `find / ...` на сервере с NFS-маунтами — поиск уйдёт в сеть надолго (используй `-xdev`).
- Путать `-mtime -1` (за последние сутки) и `-mtime 1`.
