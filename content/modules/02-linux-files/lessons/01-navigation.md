# Навигация по серверу

Первое, что делает L3 на незнакомом сервере, — понимает, **где он** и **где что лежит**. Это 30 секунд, которые экономят 30 минут.

## Где я?

```
alibek@srv-prod-01:~$ pwd
/home/alibek
alibek@srv-prod-01:~$ whoami
alibek
alibek@srv-prod-01:~$ hostname
srv-prod-01
```

Приглашение `alibek@srv-prod-01:~$` уже говорит многое: пользователь `alibek`, сервер `srv-prod-01`, каталог `~` (домашний), `$` — обычный пользователь (`#` — root).

> **Всегда проверяй `hostname` перед опасными командами.** Классика инцидентов: «я думал, что я на stage».

## Пути: абсолютные и относительные

- **Абсолютный** путь начинается с `/`: `/var/log/nginx/error.log` — работает откуда угодно.
- **Относительный** — от текущего каталога: `nginx/error.log` (если ты в `/var/log`).
- `.` — текущий каталог, `..` — родительский, `~` — домашний, `-` в `cd -` — предыдущий.

```
cd /var/log        # абсолютный путь
cd nginx           # относительный: /var/log/nginx
cd ..              # на уровень выше: /var/log
cd -               # вернуться в предыдущий каталог
cd                 # домой
```

## ls — что здесь лежит

```
ls            # список
ls -l         # подробно: права, владелец, размер, дата
ls -a         # включая скрытые (.bashrc, .env)
ls -lh        # размеры в K/M/G
ls -lt        # по времени изменения, новые сверху
ls -lS        # по размеру, большие сверху
```

Флаги можно склеивать: `ls -lah`.

## Карта Linux-сервера (FHS)

| Каталог | Что там | Зачем L3 |
|---|---|---|
| `/etc` | конфигурация (nginx, systemd, hosts) | «что поменяли в конфиге?» |
| `/var/log` | логи системы и приложений | 80% расследований начинаются тут |
| `/var/lib` | данные сервисов (БД, docker) | «кончилось место» часто здесь |
| `/opt`, `/srv` | установленные приложения, данные сайтов | код и релизы приложения |
| `/home`, `/root` | домашние каталоги | скрипты коллег, история |
| `/tmp` | временные файлы | очищается, права 777 |
| `/proc` | виртуальная ФС ядра | процессы, память |

## Как это выглядит на реальной работе L3

Тикет: «на app-03 не пишутся логи». Ты заходишь по SSH, `hostname` (тот ли сервер), `ls -lt /var/log/myapp/` (когда последний раз писались файлы, сколько весят), `ls -la /opt/myapp/` (какой релиз, кто владелец). За минуту видно: последний лог — вчера в 23:59, значит, сломалась ротация.

## Типичные ошибки

- Забыть `-a` и не увидеть `.env` или `.htaccess`.
- Путать `cd ..` и `cd /`.
- Работать в чужом каталоге с относительными путями и удалить не то.
