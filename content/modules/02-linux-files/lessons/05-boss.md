# 👹 Босс модуля: «Сервис не стартует после деплоя»

**Среда, 02:13 по времени сервера.** Ночной деплой релиза 3.2.0 магазина прошёл «успешно», но мониторинг показывает: `shop.service` в статусе **failed**, сайт отдаёт ошибки. Дежурный L2 эскалировал на тебя.

Что известно:
- Приложение — systemd-сервис `shop`, работает от пользователя **shop**.
- Деплой копирует релиз в `/opt/shop/releases/<версия>` и конфиги в `/etc/shop/`.
- До деплоя всё работало.

Твоя цепочка действий как L3:
1. Убедиться, что ты на нужном сервере и сервис действительно упал.
2. Найти причину в журнале сервиса.
3. Найти проблемный файл и понять, что с ним не так.
4. Починить **правильно** (без 777) и поднять сервис.
5. Зафиксировать причину.

Подсказка по новым командам (подробно — в модуле «Процессы и сервисы»):
```
systemctl status shop           # статус сервиса
journalctl -u shop -n 20        # последние 20 строк журнала сервиса
sudo systemctl restart shop     # перезапуск (нужен root)
```
