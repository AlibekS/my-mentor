# Диск: df, du, «место закончилось»

`No space left on device` — один из самых частых инцидентов: перестают писаться логи, падает БД, не стартуют сервисы. L3 должен за пять минут найти, **что** съело место, и безопасно его освободить.

## df — сколько свободно на файловых системах

```
$ df -h
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1        50G   48G  2.0G  96% /
/dev/sdb1       200G  120G   80G  60% /var/lib/postgresql
```

Смотри на `Use%` и `Mounted on`: проблема на `/` и на отдельном разделе — разные истории. `df -h /var/log` покажет, на каком разделе лежит каталог.

### Inodes

```
df -i
```

Место есть, а «No space left»? Закончились **inodes** — метаданные файлов. Обычно виноваты миллионы мелких файлов (сессии, кеш, очередь писем).

## du — кто занял место

```
sudo du -sh /var/*                 # размер каждого подкаталога
sudo du -sh /var/* | sort -h       # отсортировать по размеру (-h понимает K/M/G)
sudo du -h --max-depth=1 /var/log | sort -h | tail
```

Спускайся «вниз» по самому большому каталогу, пока не найдёшь виновника. Без `sudo` du не зайдёт в чужие каталоги и покажет меньше.

```
sudo find / -xdev -type f -size +1G 2>/dev/null     # большие файлы на этом разделе
```

## Что обычно съедает место

| Где | Что |
|---|---|
| `/var/log` | разросшиеся логи, сломанная ротация, debug-уровень на проде |
| `/var/lib/docker` | образы, остановленные контейнеры, логи контейнеров |
| `/var/crash`, `/var/lib/systemd/coredump` | дампы памяти после падений |
| `/tmp`, домашние каталоги | забытые выгрузки, бэкапы, дампы БД |
| `/var/lib/postgresql` | рост данных, WAL при сломанной репликации |

## Безопасная очистка

1. Сначала понять, **что** это (не удалять «большой непонятный файл» вслепую).
2. Логи: архивировать/сжать старые, обнулить текущий (`truncate -s 0` — следующий урок).
3. Дампы и временные файлы — удалить после согласования.
4. Docker: `docker system prune` (осторожно с volume).
5. Зафиксировать причину и action item (ротация, алерт на 80%).

## Как это выглядит на реальной работе L3

Алерт: `/` заполнен на 97%. `sudo du -sh /var/* | sort -h` → `/var/log 31G`. Дальше `/var/log/app` → `debug.log 28G`. Кто-то включил DEBUG на проде вчера. Ты обнуляешь файл, возвращаешь уровень INFO через change, добавляешь лог в logrotate.

## Типичные ошибки

- `du` без `sudo` — не видно половины.
- `rm` огромного лога, в который пишет процесс, — место не освободится (следующий урок).
- Удалять файлы БД или WAL «потому что большие».
