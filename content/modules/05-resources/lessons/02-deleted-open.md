# Удалённые, но открытые файлы и ротация логов

Классика: место кончилось, дежурный удалил огромный лог через `rm`, а `df` показывает те же 98%. Почему?

## Как Linux хранит файлы

Имя файла — это **ссылка** на данные. `rm` удаляет ссылку. Если файл в этот момент **открыт процессом** (он продолжает в него писать), данные живут, пока процесс не закроет файл. Место не освобождается, а в каталоге файла уже не видно.

## Как найти

```
sudo lsof +L1                # открытые файлы с 0 ссылок (удалённые)
sudo lsof | grep deleted
```

```
COMMAND   PID  USER  FD  TYPE  SIZE/OFF NLINK NAME
java     2240  shop  3w  REG  22548578304   0 /var/log/shop/debug.log (deleted)
```

## Как освободить место

1. **Перезапустить процесс** (лучше через `systemctl restart`) — он закроет старый файл и откроет новый. Самый чистый способ, но это рестарт сервиса.
2. Если рестарт нельзя: обнулить файл через дескриптор процесса — `: > /proc/<PID>/fd/<FD>` (продвинутый приём).
3. **Правильно на будущее — не удалять, а обнулять**:

```
sudo truncate -s 0 /var/log/shop/debug.log
# или
sudo sh -c ': > /var/log/shop/debug.log'
```

Файл остаётся (процесс пишет дальше), а размер сразу 0 — место освобождено.

## Ротация логов (logrotate)

Чтобы логи не разрастались: `/etc/logrotate.d/<app>`:

```
/var/log/shop/*.log {
    daily
    rotate 7
    compress
    missingok
    copytruncate      # или postrotate: systemctl reload app
}
```

`copytruncate` — копирует и обнуляет (подходит приложениям, которые не умеют переоткрывать лог). Либо приложение получает сигнал (HUP/reload) и открывает новый файл.

## Как это выглядит на реальной работе L3

Дежурный ночью сделал `rm debug.log` — место не вернулось, утром эскалация к тебе. `sudo lsof +L1` → `java 2240 ... (deleted) 21G`. Согласуешь окно, `sudo systemctl restart shop`, `df -h` — минус 21 ГБ. В тикете: причина, что сделано, и action item «настроить logrotate + запретить DEBUG на проде без change».

## Типичные ошибки

- `rm` активного лога.
- `kill -9` процесса вместо корректного рестарта.
- Забыть добавить новый лог в logrotate.
