# Docker для поддержки

Контейнер — это процесс со своей файловой системой из **образа** (image), своими переменными окружения и ограничениями ресурсов. Для L3 важно уметь быстро ответить: запущен ли контейнер, почему упал, что он пишет и с какими настройками стартовал.

## Основные команды

```
docker ps                       # запущенные контейнеры
docker ps -a                    # все, включая упавшие (Exited)
docker logs --tail 100 api      # последние строки логов (stdout/stderr контейнера)
docker logs -f api              # следить
docker inspect api              # всё о контейнере в JSON
docker inspect api --format '{{.State.ExitCode}} {{.State.OOMKilled}}'
docker exec api env             # переменные окружения внутри
docker exec nginx cat /etc/nginx/conf.d/default.conf
docker restart api
docker stats --no-stream        # CPU/память по контейнерам
```

Без членства в группе `docker` команды требуют `sudo` (в тренажёре — так).

## Статусы и коды выхода

| STATUS | Что значит |
|---|---|
| `Up 3 days` | работает |
| `Restarting (1) 10 seconds ago` | падает и перезапускается по restart policy |
| `Exited (0)` | завершился штатно |
| `Exited (1)` | ошибка приложения — смотри логи |
| `Exited (137)` | убит SIGKILL: **OOM** (лимит памяти) или `docker kill` |
| `Exited (143)` | SIGTERM — остановлен (`docker stop`) |

Отличить OOM от ручного kill: `docker inspect --format '{{.State.OOMKilled}}'` → `true`.

## Логи контейнера

Приложение в контейнере пишет в **stdout/stderr**, Docker их сохраняет — это и есть `docker logs`. Логи живут, пока существует контейнер: удалил контейнер (`docker rm`) — логов нет. Поэтому в проде логи отправляют в централизованную систему.

## Место на диске

```
docker system df           # сколько занимают образы/контейнеры, сколько можно вернуть
docker image prune -f      # удалить «висячие» образы (<none>)
docker system prune -f     # + остановленные контейнеры (осторожно)
```

Docker — частая причина «диск забит» в `/var/lib/docker`.

## Как это выглядит на реальной работе L3

«API на стейдже не отвечает». `sudo docker ps -a` → `api Exited (137)`. `inspect` → `OOMKilled: true`, лимит 256 МБ. `docker logs --tail 50 api` — перед падением загрузка большого отчёта. Решение — поднять лимит/оптимизировать выгрузку, а не просто `docker restart` раз в час.

## Типичные ошибки

- Смотреть `docker ps` без `-a` и думать, что контейнера нет.
- Перезапускать контейнер, не сохранив логи (а при пересоздании они пропадут).
- `docker system prune -a` на проде «чтобы освободить место» — удалит и нужные образы.
