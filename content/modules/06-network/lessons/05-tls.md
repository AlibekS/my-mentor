# TLS-сертификаты

HTTPS = HTTP поверх **TLS**. Сертификат доказывает, что сервер — тот, за кого себя выдаёт. «Сертификат истёк» — один из самых обидных инцидентов: предсказуемый на 100%, а ложит всё сразу.

## Что внутри сертификата

- **Subject / CN и SAN** — для каких имён выдан (`api.shop.kz`, `*.shop.kz`).
- **Issuer** — кто выдал (Let's Encrypt, DigiCert, внутренний CA).
- **Not Before / Not After** — срок действия.
- **Цепочка (chain)** — серверный сертификат → промежуточный → корневой. Сервер обязан отдать промежуточные.

## Проверка

```
curl -v https://api.shop.kz 2>&1 | grep -E "expire|subject|issuer"
openssl s_client -connect api.shop.kz:443 -servername api.shop.kz
echo | openssl s_client -connect api.shop.kz:443 2>/dev/null | openssl x509 -noout -dates
```

`-servername` важен: на одном IP много сайтов (SNI), без него получишь чужой сертификат.

## Частые ошибки TLS

| Сообщение | Причина |
|---|---|
| `certificate has expired` | истёк срок (Not After в прошлом) |
| `unable to get local issuer certificate` | сервер не отдаёт промежуточный сертификат или нет корневого у клиента |
| `certificate subject name does not match` / `no alternative certificate subject name matches` | сертификат выдан на другое имя |
| `self signed certificate` | самоподписанный (норма для внутренних стендов, не для прода) |

`curl -k` (insecure) отключает проверку — **только для диагностики**, никогда как «решение».

## Как это выглядит на реальной работе L3

В 03:00 падают все интеграции партнёров, а браузеры пользователей работают. Причина: в браузерах сертификат кешированно доверен через другую цепочку, а у партнёров — старые Java-клиенты, которым не хватает промежуточного сертификата после перевыпуска. `openssl s_client -showcerts` показывает: сервер отдаёт только один сертификат вместо двух.

Профилактика: мониторинг срока сертификатов (алерт за 21/7/1 день) и автопродление (cert-manager, certbot).

## Типичные ошибки

- «Починить» через `-k` или отключение проверки в клиенте.
- Проверять сертификат без SNI.
- Продлить сертификат и забыть перезагрузить nginx/балансировщик — он отдаёт старый из памяти.
