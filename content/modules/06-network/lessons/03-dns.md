# DNS: dig, nslookup, NXDOMAIN

«Сайт не открывается» в изрядной доле случаев — это DNS. Сначала проверь, **во что резолвится имя**.

## dig

```
dig api.shop.kz            # полный ответ
dig +short api.shop.kz     # только результат: 10.0.2.5
dig api.shop.kz MX         # почтовые записи
dig @8.8.8.8 api.shop.kz   # спросить конкретный DNS-сервер
```

Что смотреть в полном выводе:

```
;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 41022
;; ANSWER SECTION:
api.shop.kz.      300   IN   CNAME   lb-eu.shop.kz.
lb-eu.shop.kz.    300   IN   A       10.0.2.5
```

- **status**: `NOERROR` — имя есть; `NXDOMAIN` — **такого имени нет**; `SERVFAIL` — DNS-сервер не смог ответить (проблема на стороне DNS, DNSSEC и т.п.).
- **CNAME** — псевдоним: имя указывает на другое имя.
- **A / AAAA** — IPv4 / IPv6 адрес.
- **300** — **TTL** в секундах: сколько ответ можно кешировать.

`nslookup api.shop.kz` — то же попроще; есть и на Windows (удобно, когда диагностируешь у клиента).

## Где компьютер берёт ответы

1. `/etc/hosts` — локальные записи (проверяется первым! частый «сюрприз»).
2. `/etc/resolv.conf` — какие DNS-серверы спрашивать (`nameserver 10.0.0.2`).
3. Кеши: браузер, ОС, резолвер провайдера — поэтому изменения DNS расходятся не мгновенно (до TTL).

## Типичные DNS-инциденты

| Симптом | Причина |
|---|---|
| `NXDOMAIN` для нового поддомена | запись не создали / опечатка / не та зона |
| у одних клиентов работает, у других нет | DNS поменяли недавно, старый ответ в кешах до истечения TTL |
| `curl: (6) Could not resolve host` | имя не резолвится с этого сервера (resolv.conf, сеть до DNS) |
| сайт открывает старую версию | имя указывает на старый балансировщик/IP |

> Перед миграцией снижают TTL (например, до 60 с) заранее — чтобы переключение разошлось быстро.

## Как это выглядит на реальной работе L3

Клиент: «webhooks перестали приходить после вашей миграции». Ты: `dig +short hooks.shop.kz` с нашего сервера — новый IP, а клиент кешировал старый (TTL 86400 — сутки!). Временное решение — старый адрес проксирует на новый; action item — снижать TTL за сутки до миграций.

## Типичные ошибки

- Проверять DNS только со своего ноутбука (у тебя может быть VPN/другой резолвер).
- Забыть про `/etc/hosts` на сервере.
- Путать NXDOMAIN (имени нет) и таймаут (DNS недоступен).
