# HTTP и curl

## Коды ответа — первое, что смотрит L3

| Класс | Смысл | Частые |
|---|---|---|
| **2xx** | успех | 200 OK, 201 Created, 204 No Content |
| **3xx** | перенаправление | 301/302 (смотри `Location`), 304 Not Modified |
| **4xx** | ошибка **клиента** (запроса) | 400 Bad Request, 401 Unauthorized (нет/неверная аутентификация), 403 Forbidden (нет прав), 404 Not Found, 413 Payload Too Large, 429 Too Many Requests |
| **5xx** | ошибка **сервера** | 500 Internal Server Error, 502 Bad Gateway, 503 Service Unavailable, 504 Gateway Timeout |

**502 vs 503 vs 504** (за прокси/балансировщиком):
- **502** — прокси получил от бэкенда отказ соединения или битый ответ (бэкенд упал, порт закрыт).
- **503** — сервис сознательно говорит «не сейчас»: перегрузка, обслуживание, нет здоровых бэкендов.
- **504** — бэкенд **не ответил вовремя** (медленный запрос, блокировки в БД).

## curl — швейцарский нож

```
curl https://api.shop.kz/health                  # тело ответа
curl -I https://shop.kz                          # только заголовки (HEAD)
curl -i https://shop.kz                          # заголовки + тело
curl -v https://api.shop.kz/health               # подробно: DNS, TCP, TLS, запрос и ответ
curl -s -o /dev/null -w "%{http_code}\n" URL     # только код — удобно в скриптах
curl -s -w "%{time_total}\n" -o /dev/null URL    # время ответа
curl -L URL                                      # следовать редиректам
curl -X POST -H "Content-Type: application/json" -d '{"a":1}' URL
```

## Читаем curl -v

```
*   Trying 10.0.2.7:443...            ← DNS отработал, пробуем TCP
* Connected to api.shop.kz ...         ← TCP есть
* SSL certificate verify ok.           ← TLS в порядке
> GET /health HTTP/1.1                 ← > — что отправили
< HTTP/1.1 503 Service Unavailable     ← < — что получили
< Retry-After: 120
```

Где оборвалось, там и проблема:
- `Could not resolve host` (код 6) — DNS;
- `Connection refused` (7) — порт закрыт / сервис не слушает;
- `Timeout` (28) — фаервол режет или узел не отвечает;
- `SSL certificate problem` (60) — TLS (следующий урок);
- дошли до `< HTTP/1.1 5xx` — сеть в порядке, проблема в приложении.

## Как это выглядит на реальной работе L3

Клиент: «ваш API отдаёт ошибку». Первое — воспроизвести: `curl -v` с теми же URL и заголовками, что у клиента. Это сразу отделяет «у клиента сеть/прокси» от «у нас 5xx».

## Типичные ошибки

- Путать 401 и 403: 401 — «кто ты?», 403 — «знаю, кто ты, но нельзя».
- Считать 4xx нашей проблемой по умолчанию: часто это неверный запрос клиента (но массовый рост 4xx после релиза — уже наша).
- Забыть `-L` и думать, что 301 — ошибка.
