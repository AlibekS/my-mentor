# Пайпы: sort, uniq, wc, head — топ-N за одну строку

Сила Linux — в маленьких командах, соединённых **пайпами** `|`. Вывод левой команды становится входом правой.

```
команда1 | команда2 | команда3
```

## Кирпичики

| Команда | Что делает |
|---|---|
| `sort` | сортирует строки (`-n` как числа, `-r` обратно, `-k 2` по 2-му полю, `-u` уникальные) |
| `uniq` | схлопывает **соседние** одинаковые строки (`-c` — посчитать повторы) |
| `wc -l` | считает строки |
| `head -n 10` | первые 10 |
| `tail -n 10` | последние 10 |

> **`uniq` работает только с соседними строками**, поэтому почти всегда перед ним `sort`.

## Главный рецепт L3: «топ-N чего угодно»

```
<достать поле> | sort | uniq -c | sort -rn | head
```

1. достаём значения (IP, URL, код ответа, user_id);
2. `sort` — одинаковые рядом;
3. `uniq -c` — посчитать каждое;
4. `sort -rn` — по количеству, больше сверху;
5. `head` — топ-10.

Пример — топ IP в access.log (IP — первое поле, его достанет `cut -d' ' -f1` или `awk '{print $1}'`; подробно — в следующем уроке):
```
$ cut -d' ' -f1 access.log | sort | uniq -c | sort -rn | head -3
    412 45.155.205.99
    127 10.20.1.14
    118 172.16.4.21
```
Сразу видно подозрительный IP с 412 запросами.

## Сколько уникальных?

```
cut -d' ' -f1 access.log | sort -u | wc -l      # число уникальных IP
```

## Как это выглядит на реальной работе L3

Алерт «рост 404». Топ URL с 404:
```
grep '" 404 ' access.log | awk '{print $7}' | sort | uniq -c | sort -rn | head
```
Видно `/wp-login.php` — 400 раз с одного IP. Это бот-сканер, а не сломанный сайт. Ответ: «не инцидент, добавим rate-limit/блок на WAF».

## Типичные ошибки

- `uniq -c` без `sort` — числа будут неверные.
- `sort -r` вместо `sort -rn` для чисел: строковая сортировка ставит `9` выше `412`.
- Забыть `head` и вывалить 100 тысяч строк в терминал.
