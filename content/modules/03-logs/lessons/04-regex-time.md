# Регулярки, окна времени, tail -f и journalctl

## Расширенные регулярные выражения (grep -E)

| Символ | Значение | Пример |
|---|---|---|
| `.` | любой символ | `5..` — 500…599 |
| `[0-9]` | один символ из набора | `HTTP/1.[01]` |
| `*` / `+` / `?` | 0+ / 1+ / 0–1 раз | `[0-9]+ms` |
| `\|` (в -E просто `\|`→`|`) | ИЛИ | `ERROR\|FATAL` |
| `^` / `$` | начало / конец строки | `^2026-11-04 14` |
| `{n}` | ровно n раз | `[0-9]{3}` |
| `()` | группа | `(GET\|POST) /api` |

```
grep -E "ERROR|FATAL|CRIT" app.log
grep -E '" 50[234] ' access.log          # 502, 503, 504
grep -E "took=[0-9]{4,}ms" app.log       # 1000 мс и дольше
```

## Окна времени

Логи упорядочены по времени, поэтому окно можно вырезать шаблоном:

```
grep "04/Nov/2026:14:0" access.log           # 14:00–14:09
grep -E "04/Nov/2026:14:(0[5-9]|1[0-5])" access.log   # 14:05–14:15
awk '$4 >= "[04/Nov/2026:14:05" && $4 < "[04/Nov/2026:14:10"' access.log
```

Вопрос «сколько ошибок за последний час» — это окно времени + фильтр + подсчёт.

## tail -f + grep: смотреть вживую

```
tail -f /var/log/nginx/access.log | grep --line-buffered " 502 "
```

Во время инцидента: применил фикс → смотришь, перестали ли появляться 502.

## journalctl — логи systemd

Многие сервисы пишут не в файл, а в **journald**:

```
journalctl -u nginx                     # логи сервиса
journalctl -u nginx -n 50               # последние 50 строк
journalctl -u nginx -f                  # следить
journalctl -u app --since "1 hour ago"  # за последний час
journalctl -u app --since "2026-11-04 14:00" --until "14:30"
journalctl -p err                       # только ошибки и серьёзнее (err, crit, alert, emerg)
journalctl -u app -p warning --since today
```

Уровни (priority) от серьёзных к мелким: `emerg, alert, crit, err, warning, notice, info, debug`. `-p err` покажет `err` **и всё серьёзнее**.

## Как это выглядит на реальной работе L3

Клиент: «с 14:05 до 14:15 не проходили оплаты». Ты проверяешь окно:
```
grep -E "04/Nov/2026:14:(0[5-9]|1[0-4])" access.log | grep -c '" 502 '
journalctl -u payment --since "14:00" --until "14:20" -p err
```
и сопоставляешь: 502 в nginx ↔ ошибки сервиса в журнале в те же минуты.

## Типичные ошибки

- Забыть экранировать точку: `grep "1.2.3.4"` найдёт и `1x2y3z4`. Для IP: `grep -F` (фиксированная строка) или `1\.2\.3\.4`.
- Окно времени по локальному времени, а логи в UTC (или наоборот). Сверяй смещение `+0500`.
- `journalctl -p err` без `-u` — вывалит ошибки всей системы.
